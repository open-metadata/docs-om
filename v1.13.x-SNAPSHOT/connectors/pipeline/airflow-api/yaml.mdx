## Requirements

### Python Requirements

<PythonRequirements />

To run the Airflow API ingestion, you will need to install:

```bash
pip3 install "openmetadata-ingestion"
```

No additional extras are required — the connector uses only the base HTTP client.

## Metadata Ingestion

All connectors are defined as JSON Schemas.
[Here](https://github.com/open-metadata/OpenMetadata/blob/main/openmetadata-spec/src/main/resources/json/schema/entity/services/connections/pipeline/airflowApiConnection.json)
you can find the structure to create a connection to Airflow API.

In order to create and run a Metadata Ingestion workflow, we will follow
the steps to create a YAML configuration able to connect to the source,
process the Entities if needed, and reach the OpenMetadata server.

The workflow is modeled around the following
[JSON Schema](https://github.com/open-metadata/OpenMetadata/blob/main/openmetadata-spec/src/main/resources/json/schema/metadataIngestion/workflow.json)

### GCP Cloud Composer Example

For GCP Cloud Composer, use the Composer web server URL and a GCP Bearer token:

```yaml
source:
  type: airflowapi
  serviceName: cloud_composer_prod
  serviceConnection:
    config:
      type: AirflowApi
      hostPort: "https://<composer-id>-dot-<region>.composer.googleusercontent.com"
      token: "<gcp-access-token>"
      apiVersion: v2
      numberOfStatus: 10
      verifySSL: true
  sourceConfig:
    config:
      type: PipelineMetadata
      includeTags: true
sink:
  type: metadata-rest
  config: {}
workflowConfig:
  openMetadataServerConfig:
    hostPort: http://localhost:8585/api
    authProvider: openmetadata
    securityConfig:
      jwtToken: "<your-om-jwt-token>"
```

You can obtain a GCP access token using:

```bash
gcloud auth print-access-token
```

Or configure a service account with the `Composer > Composer User` role and generate a token programmatically.

### AWS MWAA Example

For AWS MWAA, use the MWAA web server URL and a web login token:

```yaml
source:
  type: airflowapi
  serviceName: mwaa_prod
  serviceConnection:
    config:
      type: AirflowApi
      hostPort: "https://<mwaa-web-server-url>"
      token: "<mwaa-web-login-token>"
      apiVersion: v1
      numberOfStatus: 10
      verifySSL: true
  sourceConfig:
    config:
      type: PipelineMetadata
      includeTags: true
sink:
  type: metadata-rest
  config: {}
workflowConfig:
  openMetadataServerConfig:
    hostPort: http://localhost:8585/api
    authProvider: openmetadata
    securityConfig:
      jwtToken: "<your-om-jwt-token>"
```

You can obtain an MWAA web login token using:

```bash
aws mwaa create-cli-token --name <your-mwaa-environment>
```

The response contains a `WebToken` and `WebServerHostname`. Use the `WebToken` as the token and `https://<WebServerHostname>` as the hostPort.

<Warning>
MWAA web tokens expire after **60 seconds**. For scheduled ingestion, use a script or Lambda to refresh the token immediately before running the workflow. Alternatively, set up an IAM role with `airflow:CreateWebLoginToken` permission for programmatic token generation.
</Warning>

### Lineage Configuration

This connector does **not** extract lineage directly. To get pipeline lineage, configure Airflow's native OpenLineage integration to send events to OpenMetadata.

**Self-hosted / Docker / Helm** — set environment variables directly:

```bash
AIRFLOW__OPENLINEAGE__TRANSPORT='{"type": "http", "url": "https://<openmetadata-host>/api/v1/openlineage/", "endpoint": "lineage", "auth": {"type": "api_key", "api_key": "<your-om-jwt-token>"}}'
AIRFLOW__OPENLINEAGE__NAMESPACE=my_airflow_instance
```

**GCP Cloud Composer** — set via Environment Overrides in the GCP Console (same variables as above).

**AWS MWAA** — cannot set `AIRFLOW__OPENLINEAGE__*` directly. Use a **startup script** or **custom Airflow plugin** that reads secrets from AWS Secrets Manager and exports the env vars. See the [main connector page](/v1.13.x-SNAPSHOT/connectors/pipeline/airflow-api#lineage-via-openlineage) for detailed MWAA instructions.

<Warning>
The `url` field **must** end with a trailing slash (`/openlineage/`). Without it, the OpenLineage HTTP client will construct an incorrect URL due to `urljoin()` behavior.
</Warning>

For full lineage setup details, platform-specific instructions, and troubleshooting, see the [main connector page](/v1.13.x-SNAPSHOT/connectors/pipeline/airflow-api#lineage-via-openlineage).
