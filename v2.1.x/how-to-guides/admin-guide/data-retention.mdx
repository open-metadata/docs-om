# Configure Data Retention

The Data Retention application removes operational records after their configured retention periods. In OpenMetadata 2.1, it also cleans up short-lived Automation Workflow records. Test Connection, Query Runner, and Reverse Ingestion runs create these records.

Data Retention is installed by default and runs weekly on Sundays at midnight.

## Configure Automation Workflow Retention

You need administrator access to configure and run the Data Retention application.

1. Click the **Profile** icon and navigate to **Settings** > **Applications** > **Data Retention**.

   <img
     src="/public/images/how-to-guides/admin-guide/data-retention/data-retention-applications-list.png"
     alt="Applications page with the Data Retention application highlighted"
   />

2. Click **Configuration**.

   <img
     src="/public/images/how-to-guides/admin-guide/data-retention/data-retention-open-configuration.png"
     alt="Data Retention application with the Configuration tab highlighted"
   />

3. Scroll to **Automation Workflow Retention Period (days)**.
4. Set the retention period:
   - Enter a positive integer to delete Automation Workflow records older than that many days.
   - Enter `0` to retain Automation Workflow records indefinitely.

    <img
      src="/public/images/how-to-guides/admin-guide/data-retention/governance-workflow-run-history-retention.png"
      alt="Data Retention configuration showing the Audit Log, Automation Workflow, and Governance Workflow Run History retention periods"
    />
5. Save the configuration.
6. Return to the Data Retention application details.
7. Optional: To apply the policy without waiting for the next scheduled run, select **Run Now**.


The default retention period is `30` days. Cleanup uses each Workflow record's last-updated time, so a record that has remained in `Pending` or `Running` beyond the retention period is also eligible for deletion.

<Warning>
Deleting expired Automation Workflow records is irreversible. This setting defaults to `30` days even for an application configuration saved before the field existed. After an upgrade, the next scheduled Data Retention run can therefore remove existing records older than 30 days. Set the value to `0` before that run if you must retain them.
</Warning>

Removing these records does not delete the service that a workflow used. OpenMetadata also cleans up the Workflow's related ownership records and stored connection secrets.

<Note>
One application run deletes at most 100,000 Automation Workflow records. Run the application again when an older installation has a larger backlog.
</Note>

## Governance Workflow Run History Retention

Governance workflows record every run and its stages. The Data Retention application deletes old runs based on a retention period that you set.

1. Open the **Configuration** tab of the Data Retention application. For the steps, see steps 1 and 2 of [Configure Automation Workflow Retention](#configure-automation-workflow-retention).
2. Scroll to **Governance Workflow Run History Retention Period (days)** and set the retention period:
    - Enter a positive integer to delete finished governance workflow runs older than that many days. The default is `30`.
    - Enter `0` to retain the run history forever.

    <img src="/public/images/how-to-guides/admin-guide/data-retention/governance-workflow-run-history-retention.png" alt="Data Retention configuration showing the Audit Log, Automation Workflow, and Governance Workflow Run History retention periods" />

3. Click **Save**.

<Warning>
Deleting expired run history is irreversible. Enter `0` to retain the history forever.
</Warning>

The application deletes a run, with all its stages, only when all of these are true:

- The run has ended, with any status other than **Running**.
- The run started before the retention cutoff. OpenMetadata keeps every run inside the retention period.
- A newer run of the same workflow exists for the same entity. Each entity keeps its latest run of each workflow, however old it is. Runs that have no entity are grouped per workflow, so the newest of those is kept too.

## Soft-Deleted Assets

When you set up a metadata agent, the **Scope & Behaviour** step has **Mark Deleted** toggles, such as **Mark Deleted Tables**, **Mark Deleted Schemas**, and **Mark Deleted Databases**. When a toggle is on, the agent soft deletes that kind of asset if it no longer exists in the source. Related items, such as test suites and lineage, are also deleted. For more information on the metadata agent options, see [How to Ingest Metadata](/v2.1.x/how-to-guides/admin-guide/how-to-ingest-metadata).

A soft-deleted asset is hidden from normal views and shows a **Deleted** badge. It is not removed. You can restore it, and its history is kept.

The Data Retention application does not permanently delete soft-deleted assets, and it has no retention period for them. No metadata agent setting turns a soft delete into a permanent delete. To remove a soft-deleted asset for good, delete it permanently yourself.

### Permanently Delete a Soft-Deleted Table in the UI

1. Open the schema that contains the table. On the **Tables** tab, turn on the **Deleted** toggle. Soft-deleted tables then appear in the list.

   <img src="/public/images/how-to-guides/admin-guide/data-retention/schema-tables-show-deleted.png" alt="Tables tab of a database schema with the Deleted toggle highlighted" />

2. Open the table.
3. Click the **⋮** icon and select **Delete**.
4. Click **Delete**.

<Warning>
A permanent delete can't be undone.
</Warning>

To permanently delete a soft-deleted schema or database, turn on the **Deleted** toggle on its parent page, open it, and delete it the same way. For a service, see the next section.

### Permanently Delete a Soft-Deleted Service in the UI

1. Select **Connections** in the left navigation bar and turn on the **Deleted** toggle. Soft-deleted services then appear in the list.

   <img src="/public/images/how-to-guides/admin-guide/data-retention/connections-show-deleted.png" alt="Connections page with the Deleted toggle turned on and highlighted" />

2. Open the service. A **Deleted** badge appears next to its name.
3. Click **Settings** > **Delete**.

   <img src="/public/images/how-to-guides/admin-guide/data-retention/deleted-service-settings-menu.png" alt="Soft-deleted service with the Settings menu open and Delete highlighted" />

4. In the dialog, **Permanently Delete** is selected. Click **Delete** to confirm.

   <img src="/public/images/how-to-guides/admin-guide/data-retention/permanently-delete-dialog.png" alt="Delete dialog for a soft-deleted service with Permanently Delete selected" />

<Warning>
A permanent delete can't be undone.
</Warning>

### Permanently Delete a Table with the API or SDK

Use either method to permanently delete a table.

- **API**: Send `DELETE /api/v1/tables/{id}?hardDelete=true`.
- **Python SDK**: Call `metadata.delete(entity=Table, entity_id=<id>, hard_delete=True)`.

Other asset types, such as schemas, databases, and services, use the same `hardDelete=true` option on their own endpoints.

## Related Retention Settings

The same application configures retention for other record types. It covers change events and activity records. It also covers test results, profile data, and audit logs. Each field is measured in days. It doesn't cover soft-deleted assets. Review every value before you run the application in a production environment.
