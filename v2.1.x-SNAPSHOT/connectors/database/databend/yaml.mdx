## Requirements

OpenMetadata connects to the Databend HTTP query service with a SQLAlchemy driver, using a username and password. The connecting user must be able to read the system and `information_schema` metadata, and to read the databases and tables you want to ingest.

### Entity Mapping

OpenMetadata ingests only the Databend `default` catalog. Databend objects map to OpenMetadata entities as follows:

| Databend | OpenMetadata |
|----------|---------|
| Catalog (`default`) | Database |
| Database | Schema |
| Tables and views | Tables |

### Profiler and Data Quality

Running the profiler workflow, data quality tests, or data diff requires `SELECT` on the tables and schemas being profiled or tested. For more information, see [Profiler Workflow](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/profiler/profiler-workflow) and [Data Quality](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/quality).

### Lineage

OpenMetadata reads table and column lineage from the lineage records that Databend keeps in `system_history.lineage_history`. Databend records lineage from its query planner, so OpenMetadata doesn't parse SQL.

Lineage requires:

- Databend v1.2.933 or later.
- A Databend Enterprise license.
- `[lineage] on = true` and `[log.history] on = true` in the Databend query configuration.
- `SELECT` on `system_history`. For example:

```sql
GRANT SELECT ON system_history.* TO <user>;
```

These requirements apply only to lineage. The metadata, profiler, and data quality workflows don't need them.

OpenMetadata creates lineage as follows:

- **View lineage**: OpenMetadata reads `CREATE VIEW` records and keeps only the current definition of each view. When **Override View Lineage** is on, OpenMetadata replaces the existing view lineage.
- **Query lineage**: OpenMetadata reads `CREATE TABLE ... AS SELECT` and data manipulation language (DML) records that fall inside the **Query Log Duration**.

The lineage agent has the following options:

- **Query Log Duration**: How far back OpenMetadata reads query lineage records. Defaults to `1`.
- **Override View Lineage**: Replaces existing view lineage. Off by default.

OpenMetadata skips the following lineage edges:

- Edges where either table isn't ingested in OpenMetadata yet. Run metadata ingestion first. A later lineage run picks up the skipped edges.
- Edges that involve an external catalog. OpenMetadata reads only the `default` catalog.
- A table that is its own source, such as an in-place update.

Schema and table filter patterns also apply to lineage.

## Metadata Ingestion
All connectors are defined as JSON Schemas.
See the [Databend connection JSON Schema](https://github.com/open-metadata/OpenMetadata/blob/main/openmetadata-spec/src/main/resources/json/schema/entity/services/connections/database/databendConnection.json) for the full set of properties.
To create and run a metadata ingestion workflow, create a YAML configuration. The configuration connects to the source, processes entities if needed, and reaches the OpenMetadata server.
The workflow is modeled around the following
[JSON Schema](https://github.com/open-metadata/OpenMetadata/blob/main/openmetadata-spec/src/main/resources/json/schema/metadataIngestion/workflow.json).

<ContentSection id={5} title="Database Schema and Connection Options" lines="10-12">

**databaseSchema**: Optional Databend database to ingest. It is also used as the initial database of the connection. When omitted, the connection starts in the `default` database and OpenMetadata scans all accessible Databend databases as schemas.

**connectionOptions**: Additional options appended to the Databend connection URL. For a non-TLS HTTP endpoint, such as the default self-hosted port `8000`, set `sslmode` to `disable`. For a TLS endpoint, set `sslmode` to `enable`.

</ContentSection>

```yaml
source:

  serviceName: local_databend
  serviceConnection:
    config:
      type: Databend
      username: <username>  # REQUIRED
      password: <password>  # REQUIRED
      hostPort: <hostPort>  # REQUIRED - format: host:port (default port 8000)
      # databaseSchema: <database>
      # connectionOptions:
      #   sslmode: disable  # disable for non-TLS HTTP (port 8000), enable for TLS
```
