## Requirements

OpenMetadata connects to ClickZetta with a SQLAlchemy driver, using a username and password and a virtual cluster to run its read-only queries. The connecting user needs to be able to use that virtual cluster and to read the catalog, the tables you want to ingest, and the query-history view.

Grant the following to the role your ingestion user connects with:

```sql
-- Allow the user's role to run queries on the virtual cluster used for ingestion
GRANT USAGE ON VCLUSTER <virtual_cluster> TO ROLE <role>;

-- Allow reading metadata and data from the schemas you want to ingest
GRANT SELECT ON SCHEMA <workspace>.<schema_name> TO ROLE <role>;
```

### Profiler and Data Quality

Running the profiler workflow, data quality tests, or data diff requires `SELECT` on the tables and schemas being profiled or tested. The profiler uses ClickZetta's native sampling to keep profiling efficient. For more information, see [Profiler Workflow](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/profiler/profiler-workflow) and [Data Quality](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/quality).

### Usage and Lineage

Query Usage and query-based lineage read from a ClickZetta query-history source. Grant `SELECT` on the query-history view you configure: `information_schema.job_history` for workspace-local history or `sys.information_schema.job_history` for cross-workspace history. For more information, see [Usage Workflow](/v2.1.x-SNAPSHOT/connectors/ingestion/workflows/usage) and [Lineage Workflow](/v2.1.x-SNAPSHOT/connectors/ingestion/workflows/lineage).

## Metadata Ingestion
All connectors are defined as JSON Schemas.
See the [ClickZetta connection JSON Schema](https://github.com/open-metadata/OpenMetadata/blob/main/openmetadata-spec/src/main/resources/json/schema/entity/services/connections/database/clickzettaConnection.json) for the structure of a ClickZetta connection.
To create and run a metadata ingestion workflow, follow these steps to create a YAML configuration that connects to the source, processes entities if needed, and reaches the OpenMetadata server.
The workflow is modeled around the following

<ContentSection id={7} title="Database Schema" lines="12">

**databaseSchema**: Optional schema restriction. When left blank, OpenMetadata attempts to scan all schemas.

</ContentSection>

<ContentSection id={8} title="Query History Table" lines="13">

**queryHistoryTable**: Optional ClickZetta table or view used for usage and query-lineage extraction. Set this to `information_schema.job_history` for workspace-local native history. Use `sys.information_schema.job_history` for cross-workspace native history. The connector maps the native columns from either source and scopes them to the configured workspace and schema. Custom tables or views must expose `query_text`, `query_type`, `user_name`, `database_name`, `schema_name`, `start_time`, `end_time`, `duration`, `aborted`, and `cost` columns.

</ContentSection>

<ContentSection id={9} title="Protocol" lines="14">

**protocol**: Protocol used to connect to ClickZetta. Choose `https` (default) or `http`.

</ContentSection>

**Connection Options (Optional)**: Enter the details for any additional connection options that can be sent to database during the connection. These details must be added as Key-Value pairs.

<CodePanel fileName="clickzetta_config.yaml">

```yaml
source:
  type: clickzetta
  serviceName: local_clickzetta
  serviceConnection:
    config:
      type: Clickzetta
      username: <username>  # REQUIRED
      password: <password>  # REQUIRED
      hostPort: <hostPort>  # REQUIRED - format: host or host:port
      databaseName: <workspace>  # REQUIRED
      virtualCluster: <virtual_cluster>  # REQUIRED
      # databaseSchema: schema
      # queryHistoryTable: information_schema.job_history
      # protocol: https  # https (default) or http
      # connectionOptions:
      #   key: value
      # connectionArguments:
      #   key: value
```
