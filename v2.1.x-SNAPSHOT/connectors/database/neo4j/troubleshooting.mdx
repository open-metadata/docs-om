## Neo4j-Specific Issues

The following issues are specific to the Neo4j connector.

### Authentication Failed

Neo4j rejected the credentials. Confirm the **Username** and **Password**, and confirm that the user isn't suspended.

### Database Not Found

Neo4j can't find the database. Confirm the **Database Name**, or leave it blank to use the home database of the user.

### Insufficient Privileges

The user isn't allowed to read the graph schema. Grant the user `ACCESS` on the database and `EXECUTE` on the `db.schema.*` procedures, `db.labels`, and `db.relationshipTypes`. The built-in `reader` role covers these.

### Certificate Not Trusted

A connection that uses Transport Layer Security (TLS) fails with "certificate verify failed" when the server uses a self-signed certificate. Use a `neo4j+ssc` or `bolt+ssc` **Connection Scheme**, which accepts self-signed certificates. Alternatively, install the certificate authority that issued the certificate on the host that runs the ingestion.

### Neo4j Is Unavailable

The server didn't accept a Bolt connection. Confirm the **Connection Scheme**, confirm the **Host and Port**, and confirm that the server is running. Neo4j Aura requires the `neo4j+s` scheme.

### Invalid Connection Configuration

Neo4j rejected the connection configuration. Check the **Connection Scheme** and the **Host and Port**.

### Columns Show the UNKNOWN Data Type

A property that has more than one type, or a type that OpenMetadata doesn't recognize, is ingested as the `UNKNOWN` data type. Ingestion doesn't fail.

### A Schema Failed to Ingest

If OpenMetadata can't read the `nodes` or the `relationships` schema, it reports the failure in the ingestion status and keeps the assets that it already ingested for that schema.
