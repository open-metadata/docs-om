## Requirements

OpenMetadata connects to the Databend HTTP query service with a SQLAlchemy driver, using a username and password. The connecting user must be able to read the system and `information_schema` metadata, and to read the databases and tables you want to ingest.

### Entity Mapping

OpenMetadata ingests only the Databend `default` catalog. Databend objects map to OpenMetadata entities as follows:

| Databend | OpenMetadata |
|----------|---------|
| Catalog (`default`) | Database |
| Database | Schema |
| Tables and views | Tables |

### Profiler and Data Quality

Running the profiler workflow, data quality tests, or data diff requires `SELECT` on the tables and schemas being profiled or tested. For more information, see [Profiler Workflow](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/profiler/profiler-workflow) and [Data Quality](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/quality).

## Metadata Ingestion

To ingest metadata from Databend, you need to create a service connection. The service connects Databend with OpenMetadata. After you create the service and deploy the metadata agent, OpenMetadata starts ingesting metadata.

### Step 1: Add New Service

1. Navigate to **Settings** > **Services**.

   <img src="/public/images/connector2.0/metadata-ingestion/access-services.png" alt="Navigate to Settings and Services" />

2. Click **Add New Service**.

   <img src="/public/images/connector2.0/metadata-ingestion/add-new-service.png" alt="Add New Service" />

### Step 2: Select a Service and Connector

From the service type dropdown, select **Database Services**, then click the **Databend** connector tile.

![Select Service](/public/images/connector2.0/metadata-ingestion/Database/select-service/databend.png)

### Step 3: Add Service Name and Description

- Enter a unique, descriptive **Service Name**. OpenMetadata identifies services by their service name. Enter a name that distinguishes this deployment from other Databend services you're ingesting metadata from.
- Optional: Enter a **Description** for the service.

![Add New Service Name](/public/images/connector2.0/metadata-ingestion/Database/service-name/databend.png)

<Note>
The service name can't be changed after it's set.
</Note>

### Step 4: Configure Connection Options

Specify your source credentials and verify the connection.

#### Enter Connection Details

Enter the connection details for Databend. The inline help panel in the UI describes each field.

The form groups fields into **Connection**, **Authentication**, **Scope & Options**, and **Advanced Config** sections.

![Configure Service Connection](/public/images/connector2.0/metadata-ingestion/Database/connection-details/databend.png)

- **Username** (required): Username to connect to Databend. The user must be able to read system and `information_schema` metadata.
- **Host and Port** (required): Host and port of the Databend HTTP query service. The default self-hosted port is `8000`, and the field is prefilled with `localhost:8000`.
- **Password** (required): Password to connect to Databend.

Expand **Scope & Options** and **Advanced Config** to set the optional fields:

![Scope and Advanced Config](/public/images/connector2.0/metadata-ingestion/Database/connection-details/databend-advanced.png)

- **Database Schema** (optional): A single Databend database to ingest. It is also used as the initial database of the connection. When left blank, the connection starts in the `default` database and OpenMetadata scans all accessible Databend databases as schemas.
- **Connection Scheme** (optional): SQLAlchemy driver scheme. The only option is `databend`, which is the default.
- **Connection Options** (optional): Additional options appended to the Databend connection URL. For a non-TLS HTTP endpoint, such as the default self-hosted port `8000`, add `sslmode` with the value `disable`. For a TLS endpoint, set `sslmode` to `enable`.
- **Connection Arguments** (optional): Additional arguments passed to the driver.

<Note>
**Note**: The **Default Database Filter Pattern** has no effect beyond the `default` catalog, because OpenMetadata ingests only that catalog.
</Note>

#### Test Connection

After you add the credentials, click **Test Connection**, then click **Save**.

<img src="/public/images/connectors/test-connection.png" alt="Test Connection" />

### Step 5: Configure Ingestion Options

In the **What to Ingest** step, configure filter rules for databases, schemas, and tables.

#### How Filter Rules Work

Each rule matches asset names using one of five match types:

- **Contains**: Matches any name containing the value. For example, `sales` matches `my_sales_data` and `sales_2024`.
- **Starts with**: Matches names beginning with the value. For example, `prod_` matches `prod_db` and `prod_schema`.
- **Ends with**: Matches names ending with the value. For example, `_raw` matches `events_raw` and `logs_raw`.
- **Is exactly**: Matches the exact name only. For example, `analytics` matches only `analytics`.
- **Matches regex**: Matches names using a regular expression. For example, `^prod_.*_v\d+$` matches `prod_events_v1`.

When include rules and exclude rules both match an asset, the exclude rule takes priority.

<Tip>
Leave all filter rules empty to ingest all databases, schemas, and tables available in the source.
</Tip>

#### Filter Options

The **Database**, **Schema**, and **Table** sections control ingestion for the corresponding asset type. Each section provides the following controls:

- **Scan Mode**: Choose one of the following scan modes:
    - **Scan all**: Ingests every asset of that type the connector can access. This is the default.
    - **Only specific**: Enables include rules so only assets matching at least one rule are ingested.
- **Exclude system toggle**: Use this toggle to automatically filter out system-reserved names defined by the connector, for example, **Exclude system databases** for the Databases section.
- **Always exclude**: Add permanent exclusion rules (shown in red). OpenMetadata never ingests assets matching these rules, regardless of include rules.
- **Preview**: View a real-time summary of what's in scope based on your current rules.
- **Include rules**: In **Only specific** mode, click **+ Add** to define a rule. Added rules appear as chips. OpenMetadata includes an asset if it matches any rule.

### Step 6: Create & Deploy

Click **Create & Deploy** to deploy the agent and start the first metadata ingestion run. OpenMetadata saves the service configuration and immediately begins pulling metadata from the source.

To monitor ingestion progress or view the service you just added, go to **Settings** > **Services** and select your service.
