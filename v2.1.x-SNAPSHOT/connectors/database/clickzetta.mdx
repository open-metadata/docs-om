## Requirements

OpenMetadata connects to ClickZetta with a SQLAlchemy driver, using a username and password and a virtual cluster to run its read-only queries. The connecting user needs to be able to use that virtual cluster and to read the catalog, the tables you want to ingest, and the query-history view.

Grant the following to the role your ingestion user connects with:

```sql
-- Allow the user's role to run queries on the virtual cluster used for ingestion
GRANT USAGE ON VCLUSTER <virtual_cluster> TO ROLE <role>;

-- Allow reading metadata and data from the schemas you want to ingest
GRANT SELECT ON SCHEMA <workspace>.<schema_name> TO ROLE <role>;
```

### Profiler and Data Quality

Running the profiler workflow, data quality tests, or data diff requires `SELECT` on the tables and schemas being profiled or tested. The profiler uses ClickZetta's native sampling to keep profiling efficient. For more information, see [Profiler Workflow](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/profiler/profiler-workflow) and [Data Quality](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/quality).

### Usage and Lineage

Query Usage and query-based lineage read from a ClickZetta query-history source. Grant `SELECT` on the query-history view you configure and make sure the user can read it:

```sql
-- Workspace-local history
GRANT SELECT ON TABLE information_schema.job_history TO ROLE <role>;
-- or cross-workspace history
GRANT SELECT ON TABLE sys.information_schema.job_history TO ROLE <role>;
```

For more information, see [Usage Workflow](/v2.1.x-SNAPSHOT/connectors/ingestion/workflows/usage) and [Lineage Workflow](/v2.1.x-SNAPSHOT/connectors/ingestion/workflows/lineage).

## Metadata Ingestion

To ingest metadata from ClickZetta, you need to create a service connection. The service connects ClickZetta with OpenMetadata. Once you create a service, OpenMetadata automatically starts ingesting metadata.

### Step 1: Add New Service

1. Navigate to **Settings** > **Services**.

   <img src="/public/images/connector2.0/metadata-ingestion/access-services.png" alt="Navigate to Settings and Services" />

2. Click **Add New Service**.

   <img src="/public/images/connector2.0/metadata-ingestion/add-new-service.png" alt="Add New Service" />

### Step 2: Select a Service and Connector

From the service type dropdown, select **Database Services**, then click the **ClickZetta** connector tile.

![Select Service](/public/images/connector2.0/metadata-ingestion/Database/select-service/clickzetta.png)

### Step 3: Add Service Name and Description

- Enter a unique, descriptive **Service Name**. OpenMetadata identifies services by their service name. Enter a name that distinguishes this deployment from other ClickZetta services you are ingesting metadata from.
- Optional: Enter a **Description** for the service.

![Add New Service Name](/public/images/connector2.0/metadata-ingestion/Database/service-name/clickzetta.png)

<Note>
The service name can't be changed after it is set.
</Note>

### Step 4: Configure Connection Options

Specify your source credentials and verify the connection.

#### Enter Connection Details

Enter the connection details for ClickZetta. The inline help panel in the UI describes each field.

![Configure Service Connection](/public/images/connector2.0/metadata-ingestion/Database/connection-details/clickzetta.png)

- **Host and Port**: Complete ClickZetta instance and service host, with an optional port (for example, `your-instance.clickzetta.com` or `your-instance.clickzetta.com:443`).
- **Username**: Username to connect to ClickZetta. It should have enough privileges to read all the metadata.
- **Workspace**: The ClickZetta workspace to ingest.
- **Virtual Cluster**: The ClickZetta virtual cluster used to run the metadata extraction queries.
- **Password**: Password to connect to ClickZetta.
- **Database Schema**: Optional schema restriction. When left blank, OpenMetadata attempts to scan all schemas.
- **Query History Table**: Optional ClickZetta table or view used for usage and query-lineage extraction. Set this to `information_schema.job_history` for workspace-local native history. Use `sys.information_schema.job_history` for cross-workspace native history. The connector maps the native columns from either source and scopes them to the configured workspace and schema. Custom tables or views must expose `query_text`, `query_type`, `user_name`, `database_name`, `schema_name`, `start_time`, `end_time`, `duration`, `aborted`, and `cost` columns.
- **Protocol**: Protocol used to connect to ClickZetta. Choose `https` (default) or `http`.

#### Advanced Configuration

Use the **Advanced Configuration** section to pass extra arguments to the connector or change the connection scheme. These settings support advanced connectivity scenarios and customizations.

- **Connection Options (Optional)**: Enter the details for any additional connection options that can be sent to database during the connection. These details must be added as Key-Value pairs.
- **Connection Arguments (Optional)**: Enter the details for any additional connection arguments such as security or protocol configs that can be sent during the connection. These details must be added as Key-Value pairs.

#### Test Connection

After you add the credentials, click **Test Connection**, then click **Save**.

<img src="/public/images/connectors/test-connection.png" alt="Test Connection" />

### Step 5: Configure Ingestion Options

In the **What to Ingest** step, configure filter rules for databases, schemas, and tables. Each rule matches asset names using one of five match types:

#### How Filter Rules Work

- **Contains**: Matches any name containing the value. For example, `sales` matches `my_sales_data` and `sales_2024`.
- **Starts with**: Matches names beginning with the value. For example, `prod_` matches `prod_db` and `prod_schema`.
- **Ends with**: Matches names ending with the value. For example, `_raw` matches `events_raw` and `logs_raw`.
- **Is exactly**: Matches the exact name only. For example, `analytics` matches only `analytics`.
- **Matches regex**: Matches names using a regular expression. For example, `^prod_.*_v\d+$` matches `prod_events_v1`.

When include and exclusion rules both match an asset, the exclusion rule takes priority.

<Tip>
Leave all filter rules empty to ingest all databases, schemas, and tables available in the source.
</Tip>

#### Filter Options

The **Database**, **Schema**, and **Table** sections control ingestion for the corresponding asset type. Each section provides the following controls:

- **Scan Mode**: Choose one of the following scan modes:
    - **Scan all**: Ingests every asset of that type the connector can access. This is the default.
    - **Only specific**: Enables include rules so only assets matching at least one rule are ingested.
- **Exclude system toggle**: Use this toggle to automatically filter out system-reserved names defined by the connector, for example, **Exclude system databases** for the Databases section.
- **Always exclude**: Add permanent exclusion rules (shown in red). Assets matching these rules are never ingested, regardless of include rules.
- **Preview**: Shows a real-time summary of what will be in scope based on your current rules.
- **Include rules**: In **Only specific** mode, click **+ Add** to define a rule. Added rules appear as chips. OpenMetadata includes an asset if it matches any rule.

### Step 6: Create & Deploy

Click **Create & Deploy** to deploy the agent and start the first metadata ingestion run. OpenMetadata saves the service configuration and immediately begins pulling metadata from the source.

To monitor ingestion progress or view the service you just added, go to **Settings** > **Services** and select your service.
