## Salesforce Data360-Specific Issues

The following issues are specific to the Salesforce Data360 pipeline connector.

### Connection Test Fails on "CheckAccess" or Authentication

OpenMetadata authenticates with the Consumer Key and Consumer Secret from your Salesforce connected app using the OAuth 2.0 client credentials flow. If the connection test fails before listing any data:

- Confirm you copied the Consumer Key and Consumer Secret correctly and haven't rotated them in Salesforce.
- Confirm the connected app has the client credentials flow and Data360 (Data Cloud) API scopes enabled.
- Check the **Salesforce Domain** value. Use `login` for production, `test` for a sandbox, or your My Domain subdomain for a custom domain.

### Pipelines Are Ingested but No Lineage Appears

Lineage links each pipeline to the tables it reads from and writes to, which requires the Data360 tables to already exist in OpenMetadata.

- Ingest metadata from Salesforce Data360 with the database connector first, then set **Data360 Database Service Name** to that service.
- For Data Streams that pull from systems outside Data360, add a **Service Mapping** entry that maps each upstream connector or data source name to the OpenMetadata service that holds it, for example `{"S3_Connector": "my-s3-service"}`.
- Data Lake Object to Data Model Object lineage is only ingested when **Include Bulk Lineage** is enabled.

### A Pipeline Is Missing or Has No Run Status

- OpenMetadata ingests only objects with an `ACTIVE` status. It filters out Data Streams, Calculated Insights, or Data Transforms in any other state and reports them in the ingestion logs.
- OpenMetadata records run status only when Data360 returns both a start and end timestamp for a run. It skips runs without a usable time window and logs them as warnings.
- OpenMetadata limits run status to the lookback window set by the ingestion's status lookback days. It doesn't ingest older runs.
