## Rill-Specific Issues

The following issues are specific to the Rill connector.

### Connection Fails Against a Rill Cloud Project

Rill Cloud requires authentication. If the test connection fails with an authorization error, confirm that an **API Token** is set and that it has read access to the project's resources. For a Rill Cloud project, **Host and Port** must point at the project endpoint (for example, `https://admin.rilldata.com/v1/orgs/<org>/projects/<project>`).

### Branch-Level Routing Is Not Supported

The connector does not support Rill Cloud branch-level routing yet. If your project URL includes a `/branch/<name>` segment, remove it so **Host and Port** ends at the project (`.../projects/<project>`).

### No Dashboards, Charts, or Data Models Are Ingested

- Confirm the token has read access to the project's resources.
- Check your filter patterns. Overly broad exclude rules, or include rules in **Only specific** mode, can filter out every dashboard, chart, or data model.

Rill exposes charts as the components used by **Canvas** dashboards. **Explore** dashboards do not define standalone components, so a project with only Explore dashboards produces no separate chart entities.

### Lineage to Source Tables Is Missing

Model-to-table lineage resolves a Rill model's SQL against tables already ingested in OpenMetadata. Make sure the upstream database service has been ingested first, and that the data model workflow is enabled so models and metrics views are extracted.
