# The Knowledge Graph Explorer

Every table in OpenMetadata carries a **Knowledge Graph** tab that renders its neighborhood as an interactive graph. It is the fastest way to see, rather than query, how one asset sits in the wider catalog.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-explorer.png" alt="Knowledge Graph tab on a table, showing the toolbar, graph canvas, and details footer" />

<Info>

The tab is **hidden unless RDF is enabled**, and is marked **Beta**. It reads from `GET /api/v1/rdf/graph/explore`, which is admin-only.

</Info>

The graph starts focused on the asset you opened it from, which is drawn with a dashed outline. A caption above the canvas names the current mode and shows the number of entities and relationships in view, for example *"20 entities · 22 relationships"*.

## The Toolbar

| Control | What it does |
|---|---|
| **Knowledge Graph / Ontology** | Switches between the technical graph and the business concept model. For more information, see [Modes](#modes). |
| **Level** | Sets how far the graph reaches from the selected asset. For more information, see [Levels](#levels). |
| **Find an entity, concept or column** | Searches the entities in view. Select a result to focus its node. |
| **Entity Type** | Filters which kinds of entity are drawn. For more information, see [Filtering](#filtering). |
| **Relationship Type** | Filters which kinds of relationship are drawn. For more information, see [Filtering](#filtering). |
| **Settings** (gear icon) | Opens the **View** menu with presentation, layout, labels, level bands, and export. For more information, see [View Settings](#view-settings). |
| **Full screen** | Expands the graph to fill the window. |

The zoom controls on the canvas zoom in and out, fit the graph to the screen, and refresh it.

## Modes

The mode switch changes what the graph is about.

| Mode | Shows |
|---|---|
| **Knowledge Graph** | Lineage, structure, governance, and business ontology connections around the asset. The default. |
| **Ontology** | The business concept model and its mapped assets. |

### Ontology Mode

Ontology mode hides the technical plumbing and draws the business model as applied to real data. Concepts are drawn as nodes, connected by typed relations such as **Broader**, **Narrower**, and **Related to**. Assets, columns, and domains that are mapped to a concept connect to it through **Has glossary term**. A concept that carries a mapping is marked **Mapped to business ontology**.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-ontology-mode.png" alt="Knowledge Graph in Ontology mode, showing a column and a domain mapped to a concept, with related concepts" />

In Ontology mode:

- A **Business concept** selector appears next to **Level** to choose which concept the graph is centered on.
- The footer drawer shows **Properties**, **Axioms**, and **Coverage** in place of **Columns**, **Relationships**, and **Gaps**.

#### Properties

Lists the declared and inherited properties of the concepts in view, with each property's **Range**, **Domain concept**, and **Cardinality**. Cardinality is shown only when the ontology declares it.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-ontology-properties.png" alt="Properties tab of the details drawer in Ontology mode" />

#### Axioms

Lists every relationship in view, ungrouped, with its **Subject**, **Predicate**, **Object**, and **Family**. Filter the list by family, for example **Ontology** or **Governance**.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-ontology-axioms.png" alt="Axioms tab of the details drawer in Ontology mode" />

#### Coverage

Lists assets missing a glossary term in the current scope, with where each asset lives, what is missing, and a suggested fix. The number next to **Coverage** in the footer is the count of unmapped assets.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-ontology-coverage.png" alt="Coverage tab of the details drawer in Ontology mode" />

## Levels

The **Level** control sets how far the graph reaches from the asset you opened it from. Each option shows its number and name in the control, for example **2 · Direct**.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-level.png" alt="Level menu open, showing 1 · Entity, 2 · Direct, and 3 · Extended" />

| Level | Shows |
|---|---|
| **1 · Entity** | The selected asset on its own. |
| **2 · Direct** | The asset and its immediate neighbors. The default. |
| **3 · Extended** | Everything within two relationship steps of the asset. |

The graph is laid out so that each level sits in its own band, and the caption in the footer reports the current level, for example *"Level 2 of 3"*. Raising the level adds an outer ring without moving the entities already on screen.

## Filtering

**Entity Type** and **Relationship Type** are multi-select filters. Each opens a searchable list with a count next to every option, a **Select all** checkbox, and **Clear all**. The button shows how many options are selected.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-entity-type-filter.png" alt="Entity Type filter open, showing grouped entity types with counts" />

- **Entity Type** groups entity types into categories such as **Governance**, **Owners**, and **Other**. Expand a category to pick individual types such as **Column** or **Domain**.
- **Relationship Type** groups relationships into families such as **Ontology**, **Governance**, **Ownership**, and **Other**. Expand a family to pick individual relationships such as **Contains**.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-relationship-type-filter.png" alt="Relationship Type filter open, showing relationship families with counts" />

Filters remove entities and relationships from the picture, but the layout of the entities that remain doesn't shift.

## Reading the Graph

These are the visual cues that show what each node and edge means.

### Relationships

Every relationship keeps its own predicate and direction, drawn as a labeled edge with an arrow. When the same predicate repeats, for example a table with seven columns, the edges are bundled into one edge with a count, such as **Has column ×7**.

### Relationship Families

The color and dash pattern of an edge show its **family**. The family button (for example **5 families**) opens a legend with the families present in the current view and how many relationships each holds.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-legend.png" alt="Legend popover listing the relationship families in view with counts" />

| Family | Covers |
|---|---|
| **Lineage** | Upstream and downstream relationships between assets. |
| **Structure** | Containment, such as a schema containing a table or a table having columns. |
| **Governance** | Tags, tiers, domains, and glossary terms applied to assets. |
| **Ownership** | Owners of assets. |
| **Ontology** | Relations between business concepts. |
| **Data Quality** | Test suites and test cases. |
| **Other** | Relationships that don't fit another family. |

Select a family in the legend to highlight it and dim the rest of the graph.

### Grouped Nodes

When many entities of one type connect to the same asset, the graph groups them into a single node with a count badge, such as **Data Assets (3)** or **Columns (7)**. A group lists the first few members and a **+N more** label.

- Select **Expand group** to draw every member as its own node.
- Select **Collapse groups** in the footer to bundle them again.

### Selecting Nodes and Edges

Selecting a node or an edge opens an inspector with its details, including its type and its relationships. For an asset, the inspector also has actions to preview the asset or open its page.

## View Settings

The gear icon opens the **View** menu.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-view-settings.png" alt="View menu with presentation, layout, relationship labels, level bands, and export" />

| Setting | Options |
|---|---|
| **Presentation** | **Balanced** bundles repeated relationships and groups many same-type entities to keep the graph readable. **Every entity** draws every entity and relationship individually. |
| **Layout** | **Connection lanes**, **Concentric**, or **Hierarchical**. |
| **Relationship labels** | **Auto labels** shows labels where there is room, **All labels** shows every label, and **No labels** hides them. Hiding a label never removes the relationship. |
| **Show level bands** | Shows or hides the shaded band and name for each level, such as **LEVEL 2 · DIRECT**. |
| **Export Graph** | Downloads the graph. For more information, see [Exporting the Graph](#exporting-the-graph). |

The footer repeats the current settings, for example *"Balanced · repeats bundled"*, how many relationships are individual and how many are bundled, and the label mode.

## The Details Drawer

The footer of the graph has a row of tabs. Select one to open a table beneath the graph, and select the close button to dismiss it. Each table has a search box.

### Columns

Lists the columns of the selected table with their type, glossary terms, and classification tags. Filter the list by **All** or **Unknown**, where **Unknown** are columns with no glossary term.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-details-columns.png" alt="Columns tab of the details drawer listing columns with type, glossary terms, and tags" />

### Relationships

Lists every relationship in view, ungrouped, with its **Subject**, **Predicate**, **Object**, and **Family**. Filter the list by family.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-details-relationships.png" alt="Relationships tab of the details drawer listing each relationship with its family" />

### Gaps

Lists assets in the current scope that have no glossary term, with where each asset lives and a **Map to a glossary term** action. The number next to **Gaps** in the footer is the count of unmapped assets.

<img src="/public/images/how-to-guides/ontology/knowledge-graph-details-gaps.png" alt="Gaps tab of the details drawer listing assets missing a glossary term" />

This is the most actionable view for a governance team. It answers "where is my ontology not applied?" on real assets, instead of as a number on a dashboard. The gaps are where an AI agent will guess, because nothing has told it what that table means.

## Status Messages

| Message | Meaning |
|---|---|
| **Partial graph · Some connections could not be returned.** | The server bounded the result. Some relationships are missing from the picture. |
| **Could not load the requested connections. Please retry.** | A request for a level or filter failed. The previous graph stays on screen. Retry the action. |
| **Updating…** | A new level or filter is loading. |

A truncated graph is labeled rather than silently misleading.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The tab is not there">
    RDF is disabled on this server, or you are not looking at a table. The tab is registered for tables and hidden when RDF is not enabled.
  </Accordion>
  <Accordion title="No knowledge graph data available">
    RDF is enabled but the graph has not been populated. Run the **RDF Knowledge Graph Indexing** application from **Settings → Applications**.
  </Accordion>
  <Accordion title="The graph is dense and hard to read">
    Drop **Level** to **1 · Entity** or **2 · Direct**, keep **Presentation** on **Balanced**, filter by **Entity Type** or **Relationship Type**, or set **Relationship labels** to **No labels**.
  </Accordion>
</AccordionGroup>

## Exporting the Graph

**Export Graph** in the **View** menu downloads the current view as **PNG**, **JSON-LD**, **Turtle**, or **CSV**. The export follows what is currently displayed. In Ontology mode, the PNG exports the view, while the other formats export the underlying entities and relationships.

To take the data with you from a script, use the export endpoint the tab reads from:

```bash
curl "$OM_HOST/api/v1/rdf/graph/explore/export?entityId={id}&entityType=table&depth=2&format=turtle" \
  -H "Authorization: Bearer $TOKEN"
```

`format` accepts `turtle` or `jsonld`. `entityTypes` and `relationshipTypes` accept comma-separated filters.
