## Overview

OpenMetadata supports Single Sign-On (SSO) integration with various identity providers, enabling secure, centralized user authentication.

You can prepare for and recover from an SSO outage by using Basic Auth. For more information, see [Recover Access During an SSO Outage](/v2.1.x-SNAPSHOT/deployment/security/basic-auth#recover-access-during-an-sso-outage).

  - **Navigate to:** **Settings** > **Single Sign-On**

<img src="/public/images/deployment/security/google/sso1.png" alt="SSO Authentication" />

  - Click your identity provider tile, such as **Google**. The configuration page for that provider opens.

## Test Login

Test Login runs a real sign-in against the configuration you entered, before you save it. It checks the configuration first, then opens the identity provider sign-in in a popup window. It doesn't create users, tokens, or sessions, and your current session stays signed in.

Test Login supports confidential OIDC, public OIDC, SAML, and LDAP configurations.

1. Fill the configuration details.
2. Click **Test Login** next to **Save**.
3. In the **Test Login** dialog, OpenMetadata validates the required fields, checks that the identity provider is reachable, and checks the credentials. The dialog lists each check as it runs, from **Configuration checked** to **Domain rules checked**, and lists every problem it finds.
4. Complete the sign-in in the popup window. For LDAP, enter an email and password in the dialog. OpenMetadata uses them once and doesn't store them.
5. When the dialog shows **You signed in successfully as {email}. These settings are safe to save.**, click **Close**, and then click **Save**.

{/* TODO IMAGE: Test Login button, progress dialog, and success dialog from the OpenMetadata UI. */}

Keep the following in mind:

- **Pop-ups**: Allow pop-ups for OpenMetadata in your browser. If the browser blocks the window, the dialog shows "The sign-in window was blocked. Allow pop-ups for this site and try again."
- **Saving**: OpenMetadata holds **Save** until a test passes when you create a configuration or change how users sign in. To save without testing, click **Save anyway**.
- **Saved secrets**: When a secret field shows the masked value, Test Login uses the saved client secret or LDAP bind password. This works only while the configuration still targets the same client.
- **Limits**: Only admins can run Test Login. Each admin can have at most 20 tests running at once, and OpenMetadata rate limits credential attempts.

<Warning>
A configuration that can't sign you in locks you out. Use **Save anyway** only when you can't run a test.
</Warning>

## Session Behavior

Users stay signed in while their identity provider session is alive. When a user's OpenMetadata session needs renewal, OpenMetadata re-authenticates them silently with the identity provider instead of signing them out. A session that OpenMetadata itself ends, such as a session limit, an admin action, or a sign-out, still signs the user out.

## Change the Provider

After you configure SSO, the **Single Sign-On** page opens on the configured provider, with **Overview** and **Configure** tabs. To switch to a different identity provider, click **Change Provider** at the top right of the page and select the new provider.

## SSO Configuration Public

This configuration is recommended for **public applications**, such as **SPAs (Single Page Applications)** and **mobile apps**. It does **not require a client secret**.

<img src="/public/images/deployment/security/google/google1.png" alt="Google SSO Configuration - Public Client" />

### 1. Client Type

- **Definition:** Defines whether the application is `Public` (no client secret) or `Confidential` (requires client secret).
- **Options:** `Public` | `Confidential`
- **Example:** `Public`
- **Why it matters:** Determines the security level and OAuth flow type.
- **Note:**
  - Choose `Public` for SPAs and mobile apps.
  - Google typically uses `Confidential` for server-side apps.
- **Note:** You can't change **Client Type** after you save the configuration.

### 2. Callback URL

- **Definition:** Redirect URL where Google sends authentication responses.
- **Example:** `https://yourapp.company.com/callback`
- **Why it matters:** Must match exactly with Google Cloud Console’s registered redirect URL.
- **Note:**
  - Must be registered under **OAuth 2.0 Client > Authorized Redirect URLs**.
  - Always use **HTTPS** in production.

### 3. Enable Self Signup

- **Definition:** Allows users to automatically create accounts on first login.
- **Options:** `Enabled` | `Disabled`
- **Example:** `Enabled`
- **Why it matters:** Controls whether new users are auto-created.
- **Note:** Set to `Disabled` for stricter access control.

### 4. Authority

- **Definition:** Google’s OAuth 2.0 authorization server.
- **Default & Example:** `https://accounts.google.com`
- **Why it matters:** Specifies where OpenMetadata should send auth requests.
- **Note:** Usually does not need to be changed.

### 5. Public Key URLs

- **Definition:** URL(s) where Google publishes its JWT signing keys.
- **Example:** `["https://www.googleapis.com/oauth2/v3/certs"]`
- **Why it matters:** Required to verify JWT token signatures.
- **Note:** Typically auto-discovered via OIDC discovery endpoint.

### 6. Token Validation Algorithm

- **Definition:** Algorithm used to validate JWT tokens.
- **Options:** `RS256` | `RS384` | `RS512`
- **Default & Example:** `RS256`
- **Why it matters:** Must match Google’s signing algorithm.
- **Note:** Google typically uses `RS256`.

### 7. JWT Principal Claims

- **Definition:** JWT fields used to identify the user.
- **Example:** `["email", "sub"]`
- **Why it matters:** Identifies the user in OpenMetadata.
- **Note:** Use `email` for consistency and compatibility. For domain scoping, use the `hd` claim.

### 8. JWT Principal Claims Mapping

- **Definition:** Maps JWT claims to OpenMetadata user attributes.
- **Example:**
  ```json

  ["email:email", "name:name", "firstName:given_name", "lastName:family_name"]

  ```
- **Why it matters:** Maps identity information to OpenMetadata user profiles.
- **Note:** Use the format `openmetadata_field:jwt_claim`.

### 9. Admin Principals

- **Definition:** List of email addresses with admin access.
- **Example:** `["admin@company.com", "superuser@company.com"]`
- **Why it matters:** Grants admin-level privileges in the system.
- **Note:** Email must match a JWT claim.

### 10. Principal Domain

- **Definition:** Default domain for constructing user emails.
- **Example:** `company.com`
- **Why it matters:** Helps form complete user identifiers from partial input.
- **Note:** Matches your Google Workspace domain.

### 11. Enforce Principal Domain

- **Definition:** Restrict login to users from a specific domain.
- **Default:** false
- **Example:** `true`
- **Why it matters:** Adds domain-level access control.
- **Note:** Use with hd parameter in custom OIDC config.

### 12. Enable Secure Socket Connection

- **Definition:** Enables SSL/TLS for secure communications.
- **Default:** false
- **Example:** `true`
- **Why it matters:** Ensures secure token exchange and communication.
- **Note:** Must be true in production.

## SSO Configuration Confidential

This configuration is required for web applications and backend services that can securely store client credentials.

<img src="/public/images/deployment/security/google/google2.png" alt="Google SSO Configuration - Confidential Client" />

### 1. Enable Self Signup

- **Definition:** Allows users to automatically create accounts on first login.
- **Options:** `Enabled` | `Disabled`
- **Example:** `Enabled`
- **Why it matters:** Controls whether new users are auto-created.
- **Note:** Set to `Disabled` for stricter access control.

### 2. Authority

- **Definition:** Google’s OAuth 2.0 authorization server.
- **Default & Example:** `https://accounts.google.com`
- **Why it matters:** Specifies where OpenMetadata should send auth requests.
- **Note:** Usually does not need to be changed.

### 3. Public Key URLs

- **Definition:** URL(s) where Google publishes its JWT signing keys.
- **Example:** `["https://www.googleapis.com/oauth2/v3/certs"]`
- **Why it matters:** Required to verify JWT token signatures.
- **Note:** Typically auto-discovered via OIDC discovery endpoint.

### 4. Token Validation Algorithm

- **Definition:** Algorithm used to validate JWT tokens.
- **Options:** `RS256` | `RS384` | `RS512`
- **Default & Example:** `RS256`
- **Why it matters:** Must match Google’s signing algorithm.
- **Note:** Google typically uses `RS256`.

### 5. OIDC Client ID

- **Definition:** OAuth 2.0 Client ID from Google Cloud Console.
- **Example:**
`123456789012-abcdefghijklmnopqrstuvwxyz123456.apps.googleusercontent.com`
- **Why it matters:** Uniquely identifies the app in the OIDC flow.

### 6. OIDC Client Secret

- **Definition:** Confidential key used to authenticate the app with Google.
- **Example:** `GOCSPX-abcdefghijklmnopqrstuvwxyz123456`
- **Why it matters:** Required for token exchange.
- **Note:**
  - Found in Google Cloud Console > Credentials.
  - Store securely and rotate periodically.

### 7. OIDC Request Scopes

- **Definition:** Permissions to request from Google during login.
- **Default:** openid email profile
- **Example:**
`openid email profile https://www.googleapis.com/auth/userinfo.email`
- **Why it matters:** Determines what user information is accessible.

### 8. OIDC Discovery URI

- **Definition:** Google OIDC metadata URL.
- **Example:** `https://accounts.google.com/.well-known/openid-configuration`
- **Why it matters:** Enables OpenMetadata to auto-discover endpoints.

### 9. OIDC Use Nonce

- **Definition:** Prevents replay attacks.
- **Default & Example:** `true`
- **Why it matters:** Enhances session-level security.

### 10. OIDC Preferred JWS Algorithm

- **Default & Example:** `RS256`
- **Why it matters:** Must match Google's token signing algorithm.

### 11. OIDC Response Type

- **Definition:** Type of OAuth response expected.
- **Options:** `id_token` | `code`
- **Default & Example:** `code`
- **Why it matters:** Defines OAuth flow; code is more secure.

### 12. OIDC Disable PKCE

- **Definition:** Disables Proof Key for Code Exchange.
- **Default & Example:** `false`
- **Why it matters:** PKCE adds protection to authorization code flow.

### 13. OIDC Max Clock Skew

- **Definition:** Allowed time difference between systems.
- **Example:** `0`
- **Why it matters:** Prevents token validation issues due to clock drift.

### 14. OIDC Client Authentication Method

- **Options:** client_secret_basic, client_secret_post, client_secret_jwt, private_key_jwt
- **Default & Example:** `client_secret_basic`
- **Why it matters:** Defines how the client secret is passed to Google.

### 15. OIDC Token Validity

- **Default:** `3600`
- **Example:** `3600 (1 hour)`
- **Why it matters:** Sets how long a token is valid.
- **Note:** Must be a positive value. OpenMetadata rejects a zero or negative value, and falls back to `3600` at runtime if an invalid value is ever persisted.

### 16. OIDC Callback URL

- **Definition:** Redirect URL where Google sends authentication responses.
- **Example:** `https://yourapp.company.com/callback`
- **Why it matters:** Must match exactly with Google Cloud Console’s registered redirect URL.
- **Note:**
  - Must be registered under **OAuth 2.0 Client > Authorized Redirect URLs**.
  - Always use **HTTPS** in production.

### 17. OIDC Max Age

- **Definition:** The `max_age` request parameter, in seconds, that OpenMetadata sends to the identity provider.
- **Default:** Empty.
- **Why it matters:** Leave it empty so the identity provider can reuse its own session. A value of `0` is treated as not set. To force users to re-enter their credentials, set **OIDC Prompt** to `login`.

### 18. OIDC Prompt

- **Options:** none, login, consent, select_account
- **Default:** Empty. Leave it empty unless you need to force a specific behavior. OpenMetadata sends `none` itself when it re-authenticates a user silently.
- **Example:** `select_account`
- **Why it matters:** Adjusts user experience during login.
- **Note:**
  - login: Always prompt credentials.
  - consent: Ask user for permission.
  - select_account: Display account picker.
  - none: Attempt silent login (may fail if not authenticated).

### 19. OIDC Session Expiry

- **Default:** 604800 (7 days)
- **Example:** `604800`
- **Why it matters:** Defines how long the user stays logged in.

### 20. End Session With Identity Provider

- **Definition:** Controls whether OpenMetadata ties a user session to the identity provider's session.
- **Default:** `false`
- **Note:**
  - Available for confidential OIDC clients only.
  - When on, OpenMetadata renews the identity provider's tokens on the provider's schedule while the user is active, and signs the user out when the provider rejects the refresh token. The token that OpenMetadata issues is shortened to that schedule, with a minimum of 120 seconds. A renewal never extends the session beyond **OIDC Session Expiry**.
  - When off, a session lasts for the configured **OIDC Session Expiry**.
  - The sign-out depends on the provider. Keycloak revokes refresh tokens together with the provider session, and Microsoft Entra ID doesn't.

### 21. JWT Principal Claims Mapping

- **Definition:** Maps JWT claims to OpenMetadata user attributes.
- **Example:**

- **Why it matters:** Maps identity information to OpenMetadata user profiles.

### Troubleshooting

If users are automatically logged out and unable to log in again due to a bad authentication configuration, you can reset the security setup using the following command:

```

./bootstrap/openmetadata-ops.sh remove-security-config --force
```

After executing the command, **restart the server**. The authentication values from your YAML or Helm chart will then be reapplied on startup.
