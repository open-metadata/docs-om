# Explore the Lineage View

OpenMetadata's Lineage view shows end-to-end data flow at both the table and column level, for Database, Dashboard, and Pipeline assets.

Search for a data asset and expand the graph to see its lineage:
- Each node expands to show its upstream and downstream edges.
- Each edge carries details such as the SQL query, pipeline information, and column-level lineage.

## Source, Target, and Edges

In the example below:
- The table on the left is the parent, or **Source** node.
- The table on the right is the **Target** node — identifiable by the arrow pointing into it.
- The arrow connecting them is the **Edge**.

Click an edge to see its details: the Source, Target, Description, and SQL Query. For a view, the SQL query shows how the target was generated from the source.

<img src="/public/images/how-to-guides/lineage/edge.png" alt="Edge Information: Source and Target" />

<Tip>
Metadata ingestion also brings in view lineage, if the database has views (data assets of the type View).
</Tip>

## Lineage Config

Use the gear icon's **Lineage Config** to change how many Upstream and Downstream Nodes this view displays, as well as the Nodes per layer. None of these fields have a fixed maximum. This only affects your current view: it resets to the platform default the next time you open a lineage graph.

To configure the lineage nodes, follow the steps below:
1. Click the **Setting** icon.

    <img src="/public/images/how-to-guides/lineage/lineage-setting.png" alt="Lineage Setting" />

2. Set the following:
    - **Upstream Depth**: Number of upstream hops shown by default when opening a lineage graph, to identify parent-level sources.
    - **Downstream Depth**: Number of downstream hops shown by default when opening a lineage graph, to identify child-level targets.
    - **Nodes Per Layer**: Maximum number of nodes shown per layer. If a layer has more nodes than this, the rest are paginated instead of all being rendered at once.

    <img src="/public/images/how-to-guides/lineage/nodes.png" alt="Lineage Config" />

To change the default for every session, see [Lineage](/v2.1.x-SNAPSHOT/how-to-guides/admin-guide/preferences/lineage).

## Filtering Lineage by Time

Open the asset from **Explore**, select the **Lineage** tab, then **Impact Analysis**. In the toolbar, use the calendar control (labeled **All time** by default) to limit the table to rows connected by lineage edges observed within a specific time range. Use it to review an asset's dependencies as of a past date or narrow the results to recent activity.

Choose one of the following:
- **All time**: No time restriction (the default).
- **Last 7 days / Last 14 days / Last 28 days**: Only rows connected by edges observed in that rolling window.
- **Custom Range**: A specific start and end date you choose.
- **Point in time**: Dependencies as of a specific date, with no start date.

The time window removes edges while OpenMetadata walks the lineage graph. It doesn't filter the results afterward. If an edge falls outside the selected window, the results exclude every asset reachable only through that edge, even if later edges fall inside the window. An asset appears in the table only if every edge on the path from your starting asset to it falls inside the window.

Edges with no timestamp always match any window for backward compatibility with legacy lineage data. A window over a mix of legacy and timestamped edges returns all legacy edges plus whichever timestamped ones fall inside the window, not a clean point-in-time snapshot.

## Impact Analysis View

The Lineage page has two tabs at the top: **Lineage** (the graph you've seen so far) and **Impact Analysis** — a table that lists the same upstream and downstream assets as rows instead of nodes on a graph, which is easier to scan, search, and sort when an asset has a large number of dependencies.

<img src="/public/images/how-to-guides/lineage/impact-analysis.png" alt="Impact Analysis table view" />

- **Upstream / Downstream**: Switch direction. Each option shows a count of how many assets lie in that direction.
- **Impact On**: Choose whether the table lists **Asset Level** impact (one row per table, pipeline, dashboard, and so on) or **Column Level** impact (one row per source-to-target column mapping).
- **Customize**: Choose which columns to show. Name (or Source/Impacted Column, in Column Level mode) always stays visible. Every other column can be toggled off.
- Search narrows the rows by asset name (Asset Level) or column name (Column Level).

**Asset Level** columns: Name, Node Depth (number of hops from the asset you're viewing), Description, Domains, Owners, Tier, Tags, and Glossary Terms.

**Column Level** columns: Source, Source Column, Impacted (the downstream or upstream asset), Impacted Column, plus the same Node Depth, Description, Domains, Owners, Tier, Tags, and Glossary Terms columns.

## Data Asset Details

Click a data asset to view its details:
- **Source, Name, Description, Owner** (team/user), **Tier**, and **Usage** information.
- Additional details based on the **type of data asset** (Table, Topic, Dashboard, Pipeline, ML Model, Container) — for example, a table's type, number of queries, and columns.
- **Data quality and profiler metrics**, including tests passed, aborted, and failed.
- **Tags** associated with the data asset.
- **Schema** details: column names, column types, and column descriptions.

## Pipeline and Dashboard Lineage

For **Pipelines**:
- Lineage first comes from the metadata ingested from the databases.
- Setting up pipeline ingestion with a database service name links the pipeline to the database tables it reads from and writes to.
- If a pipeline creates the lineage, that shows up in the edge information too.

<img src="/public/images/how-to-guides/lineage/pipeline.png" alt="Database and Pipeline Lineage" />

**Dashboards** work the same way:
- Lineage first comes from the metadata ingested from the databases.
- Dashboard ingestion then adds the data models and charts, linking them back to the database tables they're built on.

## Lineage Layers

Use the **Layers** panel to choose how the lineage map groups your assets and how much detail it shows. The panel has two selectors:

- **Lineage Layer**: Groups assets by service, domain, or data product.
- **Level**: Sets the amount of detail, from grouped nodes to individual columns.

For more information, see [Hierarchical Lineage Map](#hierarchical-lineage-map).

### Service Level View

Group assets by service to see how data moves across platforms such as Hive, Redshift, Power BI, and Tableau. This view connects ingestion, transformation, and consumption points, and gives you a system-level view of the end-to-end data journey.

<img src="/public/images/how-to-guides/lineage/lineage-map-overview.png" alt="Lineage map grouped by service" />

### Domain

Group assets by business domain, such as "Ecommerce" or "Customer Data." This view connects technical assets to the business functions they support, and helps align lineage with governance.

<img src="/public/images/how-to-guides/lineage/lineage-layer-domain.png" alt="Lineage map grouped by domain with the Domain layer selected" />

### Data Product

Group assets by data product, such as *Customer Registry* or *Superstore*. This view shows how curated, consumption-ready outputs relate to each other and where they come from.

<img src="/public/images/how-to-guides/lineage/lineage-layer-data-product.png" alt="Lineage map grouped by data product with the Data Product layer selected" />

### Field-level Lineage

Under **Level**, select **Field-level Lineage** to trace individual columns, such as `customer_id` or `first_name`, across tables and pipelines. For more information, see [Column-Level Lineage](/v2.1.x-SNAPSHOT/how-to-guides/data-lineage/column).

## Hierarchical Lineage Map

The lineage tab shows your lineage as a map you can zoom into. Instead of one large graph of every table, you start with an overview and drill down one level at a time.

<img src="/public/images/how-to-guides/lineage/lineage-map-overview.png" alt="Hierarchical lineage map at the Service Level" />

The map uses two controls that work together:

- **Lineage Layer (what you group by)**: Choose how assets are grouped. Pick **Service Level View**, **Domain**, or **Data Product**.
- **Level (how much detail you see)**: Choose how deep the map goes. Pick **Lineage Layer View**, **Data Assets**, or **Field-level Lineage**.

When you open the lineage tab for the first time, a short dialog called "Lineage, reimagined" explains these two controls. Select **Explore** to start.

### Choose a Layer and Level

1. Open the **Lineage** tab of any asset.
2. Select the **Layers** button on the graph. It shows the current layer, for example **Service Level**.
3. Under **Lineage Layer**, select how to group assets:
   - **Service Level View**: Across systems and connectors.
   - **Domain**: Across business domains.
   - **Data Product**: Across data products.
4. Under **Level**, select how much detail to show: **Lineage Layer View**, **Data Assets**, or **Field-level Lineage**.

<img src="/public/images/how-to-guides/lineage/lineage-map-layers-panel.png" alt="Layers panel with Lineage Layer and Level options" />

### Read the Map

- **Nodes**: Each node is a group or an asset, depending on the current level. Group nodes show how many assets they hold, for example "service · 1 table".
- **Rollup edges**: At the grouped level, a single line can stand for many asset-level connections. The line summarizes all the lineage between the two groups.
- **Level label**: The level you are viewing, such as **Service Level** or **Table Level**, is shown on the map.
- **Highlight**: Hover over a node to highlight the connected paths. Hover over a column at field level to highlight where it flows.
- **Recenter**: Use **Recenter on base asset** to return to the asset you started from.

### Navigate the Map

- **Zoom**: Scroll to zoom in or out.
- **Pan**: Drag the canvas to move around.
- **Drill in**: Select a group or asset to open the next level of detail. For example, select a service to see its tables, then select a table to see its columns.
- **Level control**: Use the level buttons on the map to switch between the layer, asset, and field levels. A deeper level is available only when the node you selected has something to show below it. Otherwise the tooltip reads **Zoom In**.

### Field Level View

Choose **Field-level Lineage** under **Level** to see individual columns on the map.

- **Table cards**: Each table shows its name, its location, and the number of columns it has.
- **Column list**: Expand a table to list its columns. Use **Search Columns** to find one.
- **Column lines**: A line connects a column to the columns it feeds. In the example below, `customer_id`, `first_name`, and `last_name` from `customers` feed the same columns in `customer360`.
- **Filter**: Select the filter icon on a table card to narrow the columns shown.
- **Level label**: The label next to the zoom control reads **Field Level**.

<img src="/public/images/how-to-guides/lineage/lineage-map-field-level.png" alt="Hierarchical lineage map at the Field Level" />

### Use the Breadcrumb

The breadcrumb above the graph shows the path you took, for example `All Services > Snowflake > sales > orders`.

- Select any step to jump back to that level.
- The first step, with the home icon, returns you to the top of the current layer.
- Long paths collapse automatically.

### Large Graphs

If a level has more nodes than the map can show at once, it shows a sample and tells you:

- A **+N More** badge shows how many nodes are hidden.
- A warning reads "Showing N of M assets" when the view is sampled.

Drill into a group, or narrow the view with the breadcrumb, to see the hidden assets.

### Edit Mode and Impact Analysis

- Switching to edit mode turns off the level buttons and breadcrumb. Save or cancel your edits first, then navigate.
- Use the **Impact Analysis** view for a table of upstream and downstream assets. It works the same way as before.
