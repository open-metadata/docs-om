# Create a Data Contract

Data contracts are available for tables, topics, API endpoints, dashboards, pipelines, data products, and most other data assets. For the full list and which sections each asset supports, see [Supported Assets](/v2.1.x-SNAPSHOT/how-to-guides/data-contracts/spec#supported-assets).

This guide creates a contract for a table. The form shows only the tabs an asset supports:

| Asset | Form tabs |
|---|---|
| Table | Contract Details, Terms of Service, Schema, Semantics, Security, Quality, SLA |
| Topic, API Endpoint, Dashboard Data Model | Contract Details, Terms of Service, Schema, Semantics, Security, SLA |
| Data Product and other assets | Contract Details, Terms of Service, Semantics, Security, SLA |

Creating a contract requires the **Create** permission on data contracts. Editing or running one requires **Edit All** on the contract.

## Create a Contract in the UI

1. On the asset's table details page, click the **Contract** tab.

    <img src="/public/images/how-to-guides/contracts/contract-tab.png" alt="Contract Tab" />

2. Select **Add Contract** > **Create Contract with UI**.

    <img src="/public/images/how-to-guides/contracts/create-contract.png" alt="Create Contract" />

3. On the **Contract Details** tab, do the following:
    1. Enter a **Contract Title**.
    2. Optional: Add **Owners** and a **Description**, and set the **Status**. New contracts default to **Draft**.

    <img src="/public/images/how-to-guides/contracts/contract-details.png" alt="Adding Contract Details" />

4. Optional: On the **Terms of Service** tab, describe how the data may be used.

5. On the **Schema** tab, select the columns the contract covers, or select all columns with the checkbox in the header. Only top-level columns can be selected.

    <img src="/public/images/how-to-guides/contracts/schema-tab.png" alt="Schema Tab" />

6. On the **Semantics** tab, do the following:
    1. Click **Add Semantics**.
        
        <img src="/public/images/how-to-guides/contracts/add-semantic.png" alt="Add Semantics" />

    2. Enter a suitable **Name** and **Description**. 
    3. Add a **Rule**. The rule builder checks metadata such as owners, description, domain, data product, tags, glossary terms, tier, and status.
        
        <img src="/public/images/how-to-guides/contracts/add-new-rule.png" alt="Add new rule" />

    4. Click **Save**.

    Click **Add New Rule** to add more rules to the same semantic, **Add Semantics** to add another semantic, and the toggle switch on each rule to turn it on or off.

        <img src="/public/images/how-to-guides/contracts/toggle-semantics.png" alt="Toggle semantics" />

7. Optional: On the **Security** tab, do the following:
    1. Enter a **Data Classification**.
    2. Click **Add Policy** and enter the following details:
        - **Access Policy**: Name of the access policy consumers should use.
        - **Identities**: Consumer groups or users, such as Active Directory groups.
        - **Row Filters**: Column-and-value pairs that describe which rows a consumer should see.

    <img src="/public/images/how-to-guides/contracts/security-tab.png" alt="Security Tab" />

8. On the **Quality** tab, select the table's existing test cases, or select **Add Test** to create a new [data quality test](/v2.1.x-SNAPSHOT/how-to-guides/data-quality-observability/quality/test).

    <img src="/public/images/how-to-guides/contracts/quality-tab.png" alt="Quality Tab" />

9. Optional: On the **SLA** tab, fill in the following details:
    - **Refresh Frequency**: Expected interval, in hours, days, weeks, months, or years, between data updates.
    - **Max Latency**: Maximum acceptable value, in minutes, hours, or days, between data generation and availability.
    - **Availability Time**: Time of day, such as `09:00`, and timezone by which the data should be available.
    - **Retention**: Period, in days, weeks, months, or years, the data is retained.
    - **Column**: Column that holds the data's refresh time.

    <img src="/public/images/how-to-guides/contracts/sla-tab.png" alt="SLA Tab" />

10. Click **Save**.

For what each section holds and which sections a run checks, see [Contract Sections](/v2.1.x-SNAPSHOT/how-to-guides/data-contracts/spec#contract-sections).

## Run a Contract

To check the contract now, open the actions menu on the **Contract** tab and select **Run now**.

<img src="/public/images/how-to-guides/contracts/create7.png" alt="Running an OpenMetadata Data Contract" />

A run checks the schema, semantics, and quality sections. The **Data Contract Validation** application also runs every contract daily at midnight by default. The **Contract** tab shows the result of each section and an **Execution History** chart. For what each result means, see [Running a Contract](/v2.1.x-SNAPSHOT/how-to-guides/data-contracts/spec#running-a-contract).

## Manage a Contract

- Click the **Settings** icon and the menu shows the following options:

    | Option | What it does |
    |---|---|
    | **Edit** | Opens the contract form. |
    | **Run now** | Runs the contract. |
    | **Import** | Imports a contract in the OpenMetadata YAML format. |
    | **Import ODCS** | Imports an ODCS contract. See [ODCS Import and Export](/v2.1.x-SNAPSHOT/how-to-guides/data-contracts/odcs). |
    | **Export** | Downloads the contract as OpenMetadata YAML. |
    | **Export as ODCS** | Downloads the contract as an ODCS v3.1.0 YAML file. |
    | **Delete** | Permanently deletes the contract and its run history. |

    <img src="/public/images/how-to-guides/contracts/manage-contracts.png" alt="Manage Contracts" />

- Use the view switch next to the **Settings** icon to see the contract as YAML.

    <img src="/public/images/how-to-guides/contracts/view-toggle.png" alt="YAML view" />

## Import a Contract

To create a contract from a file instead of the form, select **Add Contract** > **Import OM** for an OpenMetadata YAML file, or **Add Contract** > **Import ODCS** for an ODCS file.

<img src="/public/images/how-to-guides/contracts/import-contracts.png" alt="Import Contracts" />

When the asset already has a contract, the import asks how to apply the file:

- **Merge with Existing**: Updates the fields the file sets and keeps the rest.
- **Replace Entire Contract**: Replaces the contract with the file.
