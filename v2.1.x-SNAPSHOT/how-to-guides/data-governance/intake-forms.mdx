# Intake Forms

Intake Forms let you require specific fields to be filled in before a **Data Product**, **Domain**, or **Glossary Term** can be created or updated. Use them to make sure every new asset of these types has the ownership, classification, or descriptive metadata your organization needs from the start, instead of relying on reviewers to catch gaps after the fact.

Only one Intake Form can exist per entity type. OpenMetadata enforces it at both the API and UI layers, so a required field can't be skipped by using the API directly either.

Fields the entity's own schema already requires, such as name, description, and domain assignment, are always enforced and aren't configurable here — an Intake Form only adds further, org-specific requirements on top of them.

## Creating an Intake Form

Navigate to **Settings > Governance > Intake Forms**. Select the tab below for the entity type you want to configure. An entity type that already has a form shows as already configured and can't be selected again.

<img src="/public/images/how-to-guides/governance/intake-forms/access-intake-form.png" alt="Intake Forms card under Settings > Governance" />

<Tabs>
  <Tab title="Data Product">
    1. Click **Add Intake Form**, then select **Data Product**.
    2. Optional: Add a **Description** explaining what this form enforces.
    3. Optional: Toggle **Enabled** off to save the form without enforcing it yet. It's on by default.
    4. Under **Native Fields**, do the following. Only fields that are optional at the schema level are listed here — schema-required fields such as name and description are always enforced and don't appear.
        - Check the **Required** box for any of the following fields you want to enforce.

            | Field | Description |
            |---|---|
            | **Display Name** | Name used for display purposes. |
            | **Data Product Type** | The product's type in the Open Data Product Standard (ODPS) taxonomy, such as Dataset or Derived Data. |
            | **Visibility** | Who can discover and access the data product: Private, Invitation, Organisation, Dataspace, or Public. |
            | **Portfolio Priority** | The product's priority in the organization's data product portfolio: Critical, High, Medium, or Low. |
            | **Tags** | Tags associated with the data product. |
            | **Owners** | Owners of the data product. |
            | **Reviewers** | Users who review the data product. |
            | **Experts** | Users who are experts for the data product. |

        - Optional: Enter a custom error message for a required field, shown instead of the default message when that field is missing.

    5. Under **Custom Properties**, do the following:
        - Select **Include** for any custom property defined on Data Product that you want to add to the form.
        - Check the **Required** box for any included property that must be filled in.
        - Optional: Enter a custom error message for a required field, shown instead of the default message when that field is missing.
    6. Click **Create**.

## Managing Intake Forms

After the intake form is added, it appears in the Intake Forms list, where you can do the following:

<img src="/public/images/how-to-guides/governance/intake-forms/manage-intake-form.png" alt="Intake Forms list" />

- **Enabled** toggle: Use this to turn the form's enforcement on or off without deleting it. A disabled form doesn't block anything.
- **Actions**: In the Actions column, you can do the following:
    - **Edit**: Click the **Edit** icon, modify the details, and **Save**.
    - **Delete**: Click the **Delete** icon to remove the form entirely.

## What Happens When a Required Field Is Missing

If a required field's value is missing when someone creates or updates a matching entity, OpenMetadata rejects the request and lists which fields are missing, or shows the custom error message you set for that field, if any.
