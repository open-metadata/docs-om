# UI, Personas & Customization

For most end users, 2.1 is a visual refresh of the 2.0 interface. The changes that need action are for
teams that fork the UI, write UI plugins, run end-to-end tests, or put a proxy in front of
OpenMetadata.

The Explore page and search also changed. For more information, see
[Discovery & Search](/v2.1.x-SNAPSHOT/deployment/upgrade/breaking-changes/discovery-and-search).

## What Changed at a Glance

The table summarizes the interface changes in 2.1.

| Change | Class | Who is affected |
| --- | --- | --- |
| Ant Design (`antd`) removed from the UI | Breaking (forks and plugins) | UI forks, custom plugins |
| Add Metric and Add Custom Metric pages removed | Breaking (bookmarks) | Anyone linking to those URLs |
| List and grid page sizes standardized | Behavioral | UI tests, users of card grids |
| Many component files removed or replaced | Breaking (forks) | UI forks with deep imports |
| Reference-type custom property values stored in a new table | Behavioral | Teams that read the database directly |
| Personas report a read-only user count | Additive | API consumers |
| New routes for Context Center, Data Marketplace, announcements, and SPARQL Protocol and Resource Description Framework (RDF) Query Language (SPARQL) | Additive | Proxy and allowlist owners |

## Ant Design Removed

<Note>
**Breaking for forks and plugins.** Cosmetic for end users.
</Note>

The 2.1 UI no longer depends on `antd` (4.24), `react-antd-column-resize`, or
`@react-awesome-query-builder/antd`. Components now come from the shared
`@openmetadata/ui-core-components` package, and icons come from its `icons` export instead of
`@untitledui/icons`.

A fork or plugin that imports any of these packages, or any UI file that used them, will not build
against 2.1.

To update your fork, follow these steps:

1. Search your fork for imports of `antd`, `@untitledui/icons`, and `react-antd-column-resize`.
2. Replace them with the matching components from `@openmetadata/ui-core-components`.
3. Re-test every customized page.

Many files were removed rather than edited. They include the following:

- The old activity-feed cards
- The lineage node suggestion sidebar
- The legacy landing-page widgets
- The Quick Filter dropdown on Explore
- The search settings term boost editor
- The KnowledgeGraph3D components
- The `AlertBar`

<Note>
Expect widespread `data-testid` and page-structure changes. Plan time to update your end-to-end tests.
</Note>

## Add Metric and Add Custom Metric Pages Removed

<Note>
**Breaking.** Affects bookmarks, saved links, and documentation that point to these pages.
</Note>

These routes no longer exist in the 2.1 UI:

- `/metrics/add-metric`
- `/add-custom-metric/:dashboardType/:fqn`

A saved link to either URL no longer opens a form. Both forms now open as a side drawer. You create a
metric from the **Metrics** page and add a custom metric from the table's **Profiler** tab. Link to
those pages instead of the old URLs.

## Page Sizes

<Note>
**Behavioral.** Affects every paginated list and grid.
</Note>

The UI defines list page sizes of 15, 25, and 50 rows and card grid sizes of 12, 24, and 48
items. The fixed nine-card grid size from 2.0 is gone, so grids that showed nine cards per page now show 12.

<Note>
UI tests that select a specific page size, or count the cards on a grid page, need the new values.
</Note>

## New Routes

<Info>
**Additive.** Affects navigation, reverse proxies, and path allowlists.
</Info>

| Route | Purpose |
| --- | --- |
| `/context-center/ai-context` and `/context-center/ai-context/:fqn` | AI context pages, moved from persona settings |
| `/data-marketplace/data-access-requests` | Data access requests in the Data Marketplace |
| `/settings/notifications/announcements` (with `add`, `edit/:id`, `duplicate/:id`) | Manage announcements from Settings |
| `/settings/default-time-format` | Default time format setting |
| `/governance/sparql` | SPARQL playground |

If you put a proxy that allowlists paths in front of OpenMetadata, add the routes your users need. The UI is
a single-page app, so deep links to these routes also need your proxy to serve `index.html`.

## Personas and Custom Properties

<Note>
**Behavioral** (database readers) and **Additive** (API). No change is needed for most teams.
</Note>

- Reference custom property values move to a new table. Values of custom properties of type
  Entity Reference and Entity Reference List are now stored only in a new `custom_property_reference`
  table, one row per referenced asset. They no longer live in the `entity_extension` table or in the
  copy kept inside each column record. The 2.1 upgrade moves existing values automatically. A reference
  whose target asset no longer exists is dropped during the move, and a hard delete of an asset now
  removes the references that point to it. Values of every other custom property type stay where they
  were.
  - Teams that query these values straight from the database, for example in reports or
    scripts, are affected. Read them through the API instead, or point your queries at the new table.
- Personas gain a read-only `userCount` field. The API can now return the number of distinct
  active users who have the persona. This counts users assigned directly, through a team, or as their default persona. It is calculated on request and does not change who has the persona.

Persona customization (landing page, navigation items, and widgets) and custom property types are
unchanged in 2.1.

## Other Behavior Changes

<Note>
**Behavioral.** Affects fork maintainers.
</Note>

- Requests can opt out of the navbar domain filter by sending the `X-Skip-Domain-Filter` header. The UI
  removes it before the request is sent to the server.
- The user preferences store gains a separate saved grid page size, plus saved choices for the natural
  language search toggle, 12h/24h time format, and lineage temporary tables.
- The persona AI-context components moved from the persona settings folder to
  `components/ContextCenter`. Deep imports from the old location will not resolve.
