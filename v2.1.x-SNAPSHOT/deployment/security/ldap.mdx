# Setting up Ldap Authentication
<Warning>

Security requirements for your **production** environment:
- **DELETE** the admin default account shipped by OM in case you had [Basic Authentication](/v2.1.x-SNAPSHOT/deployment/security/basic-auth)
  enabled before configuring the authentication with Auth0 SSO.
- **UPDATE** the Private / Public keys used for the [JWT Tokens](/v2.1.x-SNAPSHOT/deployment/security/enable-jwt-tokens). The keys we provide
  by default are aimed only for quickstart and testing purposes. They should NEVER be used in a production installation.

</Warning>

OpenMetadata allows using LDAP for validating email and password authentication.
Once setup successfully, the user should be able to sign in to OpenMetadata using the Ldap credentials.

## Map LDAP and Active Directory Groups to Roles

By default, every LDAP user gets no OpenMetadata roles. To grant roles automatically, map directory groups to OpenMetadata roles. OpenMetadata looks up the groups each user belongs to and assigns the mapped roles.

Set these fields in `ldapConfiguration`:

| Field | Environment variable | Description |
|-------|----------------------|-------------|
| `groupBaseDN` | `AUTHENTICATION_GROUP_LOOKUP_BASEDN` | Base DN where OpenMetadata searches for groups, for example `ou=groups,dc=example,dc=com`. |
| `groupAttributeName` | `AUTHENTICATION_USER_GROUP_ATTR` | Attribute that identifies a group entry, for example `objectClass`. |
| `groupAttributeValue` | `AUTHENTICATION_USER_GROUP_ATTR_VALUE` | Value of that attribute for group entries, for example `groupOfNames`. |
| `groupMemberAttributeName` | `AUTHENTICATION_USER_GROUP_MEMBER_ATTR` | Group attribute that lists its members, for example `member`. |
| `authRolesMapping` | `AUTH_ROLES_MAPPING` | JSON object that maps group DNs to OpenMetadata role names. |
| `authReassignRoles` | `AUTH_REASSIGN_ROLES` | Roles that are reset from the directory every time a user signs in. |
| `roleAdminName` | `AUTHENTICATION_USER_ROLE_ADMIN_NAME` | Role name in `authRolesMapping` that makes the user an OpenMetadata admin, for example `Admin`. |
| `allAttributeName` | `AUTHENTICATION_USER_ALL_ATTR` | Value you can list in `authReassignRoles` to reassign all roles and the admin flag. |

### Example

`authRolesMapping` is a JSON object. Each key is the full DN of a group. Each value is a list of role names that exist in OpenMetadata:

```json
{
  "cn=admins,ou=groups,dc=example,dc=com": ["Admin"],
  "cn=analysts,ou=groups,dc=example,dc=com": ["DataConsumer"],
  "cn=stewards,ou=groups,dc=example,dc=com": ["DataSteward", "DataConsumer"]
}
```

With this mapping and `authReassignRoles: ["Admin", "DataConsumer", "DataSteward"]`:

- A user in `cn=analysts` gets the `DataConsumer` role.
- A user in `cn=stewards` gets the `DataSteward` and `DataConsumer` roles.
- A user in `cn=admins` becomes an OpenMetadata admin.

Role names are case-sensitive. If a role in the mapping doesn't exist in OpenMetadata, the server skips it and logs `Role <name> does not exist in OM Database`.

### When Roles Are Applied

- **First login**: When a user signs in for the first time, OpenMetadata creates the user and assigns every role mapped from their groups.
- **Later logins**: OpenMetadata assigns roles again only for the roles listed in `authReassignRoles`. For those roles, group changes in the directory take effect at the next sign-in, including removals. Roles you assign in OpenMetadata that aren't in `authReassignRoles` are kept.
- **Leave `authReassignRoles` empty** to assign roles only on first login. Later changes to a user's groups don't change their roles.
- **Add the `allAttributeName` value** to `authReassignRoles` to reset all roles, and the admin flag, from the directory at every login.

A user's roles change at the next sign-in, not while they're signed in. To apply a group change right away, ask the user to sign out and sign in again.

<Note>
`authRolesMapping` and `authReassignRoles` are not editable from the UI. Set them in the server configuration for your deployment: environment variables for [Docker](/v2.1.x-SNAPSHOT/deployment/security/ldap/docker#map-ldap-groups-to-roles-optional), Helm values for [Kubernetes](/v2.1.x-SNAPSHOT/deployment/security/ldap/kubernetes#map-ldap-groups-to-roles-optional), or `openmetadata.yaml` for [Bare Metal](/v2.1.x-SNAPSHOT/deployment/security/ldap/bare-metal#map-ldap-groups-to-roles-optional). Restart the server after you change them.
</Note>
