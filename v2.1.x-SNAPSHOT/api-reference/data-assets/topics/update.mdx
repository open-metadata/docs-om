# Update a Topic

Create a topic or update it if it already exists, using `PUT /v1/topics` with the full request body. Send the complete definition, not just the fields you want to change. To change only some fields, use `PATCH` with a JSON Patch array and the `application/json-patch+json` content type, as shown in the PATCH examples below.

## Body Parameters

<ParamField body="name" type="string" required>
  Name of the topic. Must be unique within the parent messaging service.
</ParamField>

<ParamField body="service" type="string" required>
  Fully qualified name of the parent MessagingService, for example `sample_kafka`.
</ParamField>

<ParamField body="messageSchema" type="object">
  Schema definition for messages in the topic.

  <Expandable title="properties">
    <ParamField body="schemaType" type="string">
      Type of schema, for example `Avro`, `Protobuf`, `JSON`, `Other`.
    </ParamField>

    <ParamField body="schemaText" type="string">
      The schema definition text.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="partitions" type="integer" required>
  Number of partitions for the topic.
</ParamField>

<ParamField body="cleanupPolicies" type="array">
  Array of cleanup policies for the topic, for example `delete`, `compact`.
</ParamField>

<ParamField body="replicationFactor" type="integer">
  Replication factor for the topic.
</ParamField>

<ParamField body="maximumMessageSize" type="integer">
  Maximum message size in bytes.
</ParamField>

<ParamField body="retentionSize" type="integer">
  Retention size in bytes. Use `-1` for unlimited.
</ParamField>

<ParamField body="displayName" type="string">
  Human-readable display name for the topic.
</ParamField>

<ParamField body="description" type="string">
  Description of the topic in Markdown format.
</ParamField>

<ParamField body="owners" type="array">
  Array of owner references (users or teams) to assign to the topic.

  <Expandable title="properties">
    <ParamField body="id" type="string">
      UUID of the owner entity.
    </ParamField>

    <ParamField body="type" type="string">
      Type of owner entity, for example `user`, `team`.
    </ParamField>

    <ParamField body="name" type="string">
      Name of the owner entity.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="domains" type="array">
  Fully qualified names of the domains to assign for governance purposes.
</ParamField>

<ParamField body="tags" type="array">
  Array of classification tags to apply to the topic.

  <Expandable title="properties">
    <ParamField body="tagFQN" type="string" required>
      Fully qualified name of the tag.
    </ParamField>

    <ParamField body="labelType" type="string">
      Type of label, for example `Manual`, `Derived`, `Propagated`.
    </ParamField>

    <ParamField body="state" type="string">
      State of the tag, for example `Suggested`, `Confirmed`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="extension" type="object">
  Custom property values defined by your organization's metadata schema.
</ParamField>

<RequestExample dropdown>
```bash PUT /v1/topics
curl -X PUT "{base_url}/api/v1/topics" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "address_book",
    "service": "sample_kafka",
    "description": "All Protobuf record related events gets captured in this topic",
    "messageSchema": {
      "schemaType": "Protobuf",
      "schemaText": "syntax = \"proto2\";\npackage tutorial;\nmessage Person { ... }"
    },
    "partitions": 1,
    "cleanupPolicies": ["delete"],
    "replicationFactor": 1,
    "maximumMessageSize": 1,
    "retentionSize": -1
  }'
```

```python PATCH /v1/topics/{id}
from metadata.generated.schema.entity.services.connections.metadata.openMetadataConnection import (
    AuthProvider,
    OpenMetadataConnection,
)
from metadata.generated.schema.security.client.openMetadataJWTClientConfig import (
    OpenMetadataJWTClientConfig,
)
from metadata.ingestion.ometa.ometa_api import OpenMetadata
from metadata.generated.schema.entity.data.topic import Topic
from metadata.generated.schema.type.schema import SchemaType, Topic as TopicSchema

metadata = OpenMetadata(
    OpenMetadataConnection(
        hostPort="https://your-company.open-metadata.org/api",
        authProvider=AuthProvider.openmetadata,
        securityConfig=OpenMetadataJWTClientConfig(jwtToken="your-jwt-token"),
    )
)

# Retrieve, modify, and update
topic = metadata.get_by_id(entity=Topic, entity_id="0a021819-982e-4ee4-a5a2-4af30eaa3016")
modified = topic.model_copy(deep=True)
modified.description = "Updated: All Protobuf record events captured with enhanced schema"
modified.messageSchema = TopicSchema(
    schemaType=SchemaType.Protobuf,
    schemaText="syntax = \"proto3\";\npackage tutorial;\nmessage Person { ... }"
)
updated = metadata.patch(entity=Topic, source=topic, destination=modified)

if updated is None:
    print("No changes were applied")
else:
    print(f"Updated to version {updated.version.root}")
```

```java PATCH /v1/topics/{id}
import org.openmetadata.schema.entity.data.Topic;

// client is an initialized OpenMetadataClient.

// Retrieve, modify, and update
Topic topic = client.topics().get("0a021819-982e-4ee4-a5a2-4af30eaa3016");
topic.setDescription("Updated: All Protobuf record events captured with enhanced schema");
Topic updated = client.topics().update(topic.getId(), topic);
```

```bash PATCH /v1/topics/{id}
# Update by ID
curl -X PATCH "{base_url}/api/v1/topics/0a021819-982e-4ee4-a5a2-4af30eaa3016" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "replace", "path": "/description", "value": "Updated: All Protobuf record events captured with enhanced schema"}
  ]'

# Update by name
curl -X PATCH "{base_url}/api/v1/topics/name/sample_kafka.address_book" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "replace", "path": "/description", "value": "Updated: All Protobuf record events captured with enhanced schema"}
  ]'
```

## Returns

Returns the updated topic object with the new version number.

## Response

<ResponseField name="id" type="string">
  Unique identifier for the topic (UUID format).
</ResponseField>

<ResponseField name="name" type="string">
  Topic name.
</ResponseField>

<ResponseField name="fullyQualifiedName" type="string">
  Fully qualified name in format `service.topicName`.
</ResponseField>

<ResponseField name="description" type="string">
  Updated description.
</ResponseField>

<ResponseField name="version" type="number">
  Incremented version number.
</ResponseField>

## Error Handling

| Code | Error Type | Description |
|------|-----------|-------------|
| `400` | `BAD_REQUEST` | Invalid or malformed request body |
| `401` | `UNAUTHORIZED` | Invalid or missing authentication token |
| `403` | `FORBIDDEN` | User lacks permission to update this topic |
| `409` | `CONFLICT` | Concurrent modification detected |
