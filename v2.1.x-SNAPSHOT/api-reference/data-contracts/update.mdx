# Update a Data Contract

Create a data contract or update it if it already exists, using `PUT /v1/dataContracts` with the full request body. Send the complete definition, not just the fields you want to change. To change only some fields, use `PATCH` with a JSON Patch array and the `application/json-patch+json` content type, as shown in the PATCH examples below.

## Body Parameters

<ParamField body="name" type="string" required>
  Name of the data contract, 1 to 256 characters. The contract's fully qualified name is `<entityFQN>.dataContract_<name>`.
</ParamField>

<ParamField body="entity" type="object" required>
  Reference to the data asset this contract applies to. An entity can have only one contract.

  <Expandable title="properties">
    <ParamField body="id" type="string" required>
      UUID of the entity.
    </ParamField>

    <ParamField body="type" type="string" required>
      Entity type. See [Supported Entity Types](/v2.1.x-SNAPSHOT/api-reference/data-contracts#supported-entity-types).
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="displayName" type="string">
  Human-readable display name.
</ParamField>

<ParamField body="description" type="string">
  Description in Markdown format.
</ParamField>

<ParamField body="entityStatus" type="string" default="Draft">
  Contract status: `Draft`, `In Review`, `Approved`, `Rejected`, `Deprecated`, or `Archived`.
</ParamField>

<ParamField body="schema" type="array">
  Expected columns or fields. Supported for `table`, `topic`, `apiEndpoint`, and `dashboardDataModel` only. Each item follows the Column schema. Every name must exist on the entity, and no name can repeat.

  <Expandable title="properties">
    <ParamField body="name" type="string" required>
      Column or field name.
    </ParamField>

    <ParamField body="dataType" type="string" required>
      Data type, for example `INT`, `VARCHAR`, or `TIMESTAMP`.
    </ParamField>

    <ParamField body="dataLength" type="integer">
      Length for types such as `VARCHAR`.
    </ParamField>

    <ParamField body="constraint" type="string">
      Constraint: `NULL`, `NOT_NULL`, `UNIQUE`, `PRIMARY_KEY`.
    </ParamField>

    <ParamField body="description" type="string">
      Column description.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="semantics" type="array">
  Semantics rules evaluated against the entity's metadata when the contract is validated.

  <Expandable title="properties">
    <ParamField body="name" type="string" required>
      Rule name.
    </ParamField>

    <ParamField body="description" type="string" required>
      Rule description. Reported as the failure reason when the rule fails.
    </ParamField>

    <ParamField body="rule" type="string" required>
      [JSON Logic](https://jsonlogic.com/) expression. The rule passes when it returns `true`.
    </ParamField>

    <ParamField body="enabled" type="boolean" default="true">
      Whether the rule is evaluated.
    </ParamField>

    <ParamField body="entityType" type="string">
      Apply the rule only to this entity type.
    </ParamField>

    <ParamField body="ignoredEntities" type="array">
      Entity types the rule skips.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="qualityExpectations" type="array">
  References to test cases that must pass. Supported for `table` only.

  <Expandable title="properties">
    <ParamField body="id" type="string" required>
      UUID of the test case.
    </ParamField>

    <ParamField body="type" type="string" required>
      Must be `testCase`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="sla" type="object">
  Service level agreement expectations. Stored and shown on the contract. Validation runs check it for tables, except retention.

  <Expandable title="properties">
    <ParamField body="refreshFrequency" type="object">
      `interval` (integer) and `unit`: `hour`, `day`, `week`, `month`, or `year`.
    </ParamField>

    <ParamField body="maxLatency" type="object">
      `value` (integer) and `unit`: `minute`, `hour`, or `day`.
    </ParamField>

    <ParamField body="availabilityTime" type="string">
      Time of day the data should be available, for example `09:00`.
    </ParamField>

    <ParamField body="timezone" type="string" default="GMT+00:00 (Europe/London)">
      Timezone for `availabilityTime`, in the form `GMT+05:30 (Asia/Kolkata)`.
    </ParamField>

    <ParamField body="retention" type="object">
      `period` (integer) and `unit`: `day`, `week`, `month`, or `year`.
    </ParamField>

    <ParamField body="columnName" type="string">
      Column that holds the data's refresh time.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="termsOfUse" type="string">
  Terms of use in Markdown format. Describes allowed and disallowed uses and compliance requirements. Returned as `termsOfUse.content` on the contract.
</ParamField>

<ParamField body="security" type="object">
  Security and access expectations. Stored and shown on the contract, but not enforced.

  <Expandable title="properties">
    <ParamField body="dataClassification" type="string">
      Classification of the data, for example `PII` or `Confidential`.
    </ParamField>

    <ParamField body="policies" type="array">
      Access policies. Each has `accessPolicy` (policy name), `identities` (consumer groups or users), and `rowFilters` (a list of `columnName` and `values`).
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="owners" type="array">
  Owner references (users or teams).
</ParamField>

<ParamField body="reviewers" type="array">
  Reviewer references (users or teams). When set, only a reviewer can move the contract from `In Review` to `Approved` or `Rejected`.
</ParamField>

<ParamField body="effectiveFrom" type="string">
  Date and time from which this contract is effective. Informational only.
</ParamField>

<ParamField body="effectiveUntil" type="string">
  Date and time until which this contract is effective. Informational only.
</ParamField>

<ParamField body="sourceUrl" type="string">
  Link to where the contract is maintained.
</ParamField>

<RequestExample dropdown>
```bash PUT /v1/dataContracts
curl -X PUT "{base_url}/api/v1/dataContracts" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "sales-orders-contract",
    "entity": {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "type": "table"
    },
    "description": "Data contract for the sales orders table",
    "entityStatus": "Approved",
    "schema": [
      {"name": "order_id", "dataType": "INT", "constraint": "PRIMARY_KEY"},
      {"name": "order_date", "dataType": "TIMESTAMP", "constraint": "NOT_NULL"}
    ],
    "semantics": [
      {
        "name": "Owners is set",
        "description": "The table must have an owner.",
        "rule": "{\"and\":[{\"some\":[{\"var\":\"owners\"},{\"!=\":[{\"var\":\"fullyQualifiedName\"},null]}]}]}",
        "enabled": true
      }
    ],
    "sla": {
      "refreshFrequency": {"interval": 1, "unit": "day"}
    }
  }'
```

```python PATCH /v1/dataContracts/{id}
from metadata.sdk import configure
from metadata.sdk.entities import DataContracts

configure(
    host="https://your-company.open-metadata.org/api",
    jwt_token="your-jwt-token"
)

# Update contract description and status
contract = DataContracts.retrieve("f7a1b2c3-d4e5-6789-0abc-def123456789")
contract.description = "Updated contract for sales orders table"
contract.entityStatus = "Approved"
contract = DataContracts.update(contract)
```

```java PATCH /v1/dataContracts/{id}
import static org.openmetadata.sdk.fluent.DataContracts.*;

// Update using fluent API
FluentDataContract contract = find(contractId).fetch();
contract.withDescription("Updated contract for sales orders table")
    .withStatus(EntityStatus.APPROVED)
    .save();
```

```bash PATCH /v1/dataContracts/{id}
# Update description
curl -X PATCH "{base_url}/api/v1/dataContracts/f7a1b2c3-d4e5-6789-0abc-def123456789" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "replace", "path": "/description", "value": "Updated contract for sales orders table"},
    {"op": "replace", "path": "/entityStatus", "value": "Approved"}
  ]'

# Add a semantic rule
curl -X PATCH "{base_url}/api/v1/dataContracts/f7a1b2c3-d4e5-6789-0abc-def123456789" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "add", "path": "/semantics/-", "value": {
      "name": "Domain is set",
      "description": "The table must belong to a domain.",
      "rule": "{\"some\":[{\"var\":\"domains\"},{\"!=\":[{\"var\":\"fullyQualifiedName\"},null]}]}",
      "enabled": true
    }}
  ]'
```
</RequestExample>

## Common Patch Operations

| Operation | Path | Description |
|-----------|------|-------------|
| `replace` | `/description` | Update description |
| `replace` | `/entityStatus` | Change status (`Draft`, `In Review`, `Approved`, `Rejected`, `Deprecated`, `Archived`) |
| `add` | `/semantics/-` | Add a semantic rule |
| `remove` | `/semantics/0` | Remove a semantic rule by index |
| `replace` | `/sla` | Update SLA section |
| `add` | `/schema/-` | Add a schema column |

## Error Handling

| Code | Error Type | Description |
|------|-----------|-------------|
| `400` | `BAD_REQUEST` | Invalid or malformed request body |
| `401` | `UNAUTHORIZED` | Invalid or missing authentication token |
| `403` | `FORBIDDEN` | User lacks permission to update data contracts |
