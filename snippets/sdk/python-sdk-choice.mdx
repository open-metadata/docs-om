## Which Python SDK Should I Use?

The `openmetadata-ingestion` package contains two Python clients. Both talk to the same OpenMetadata API.

| | Original client | SDK 2.0 |
|---|---|---|
| Import | `metadata.ingestion.ometa.ometa_api.OpenMetadata` | `metadata.sdk` |
| Setup | Build an `OpenMetadataConnection` and pass it to `OpenMetadata(...)` | Call `configure(host=..., jwt_token=...)` once |
| Style | Generic methods that take an entity type, such as `metadata.get_by_name(entity=Table, fqn=...)` | One class per entity, such as `Tables.retrieve_by_name(fqn)` |
| Available since | Every release | OpenMetadata 1.10.0 |

For new scripts and jobs, use SDK 2.0. It needs less setup and reads more simply. Use the original client when you need an operation that SDK 2.0 doesn't offer yet, or when you maintain existing code that already uses it.

### Using Both Clients in One Script

Both ship in the same package, so one script can use both. Set up each one separately: call `configure()` for SDK 2.0 and build an `OpenMetadata` client for the original client.

### Migrating an Existing Job

Change one call at a time:

| Original client | SDK 2.0 |
|---|---|
| `metadata.create_or_update(data=request)` | `Tables.create(request)` |
| `metadata.get_by_id(entity=Table, entity_id=id)` | `Tables.retrieve(id)` |
| `metadata.get_by_name(entity=Table, fqn=fqn)` | `Tables.retrieve_by_name(fqn)` |
| `metadata.list_all_entities(entity=Table)` | `Tables.list_all()` |
| `metadata.list_entities(entity=Table, params={...})` | `Tables.list(filters={...})` |
| `metadata.delete(entity=Table, entity_id=id)` | `Tables.delete(id)` |

`Tables.create(request)` also updates an existing table, the same as `create_or_update`.

Three details differ from what you might expect:

- In `configure(host=...)`, include `/api` at the end of the URL, the same as `hostPort` in the original client.
- When you list entities, pass query filters as `filters={"databaseSchema": "service.database.schema"}` and read the results from `.entities`.
- With the original client, set `authProvider="openmetadata"` when you authenticate with a JWT token. SDK 2.0 doesn't need an `authProvider`.
