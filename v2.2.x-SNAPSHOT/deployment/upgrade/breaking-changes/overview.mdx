# Breaking Changes: 2.0 to 2.1

OpenMetadata 2.1 removes the old Feed API and retires the Delta Lake connector. It also moves user sign-in
toward email-based identity and tightens permission checks on search and lineage. It adds an ontology and an
approval-gated change model.

This section documents every change that can break an existing client, script, deployment, or user
workflow. The changes are broken out by component, so you only have to read the parts that apply to you.
They are compared against OpenMetadata 2.0.9, the latest 2.0 release.

<Warning>
Take a full database backup before upgrading. The 2.1.0 migration makes the following changes:

- Renames `thread_entity_legacy` to `thread_entity_archived`
- Creates new tables
- Rewrites task, lineage, alert, and application rows
- Changes the MySQL default collation

To roll back, restore the backup.
</Warning>

## How to Read This Section

Every entry is classified so you can triage quickly.

| Class | Meaning |
| --- | --- |
| **Breaking** | Existing callers or configurations fail outright. Action is required before or during the upgrade. |
| **Behavioral** | Requests still succeed, but the result, ordering, permissions, or side effect differs. |
| **Deprecated** | Still works in 2.1, scheduled for removal. Migrate at your convenience. |
| **Additive** | New surface only. Listed where it replaces something you may currently be using. |

Each entry states **what changed**, **who is affected**, and **what to do**.

## Deprecation Notices

<Note>
Airflow as the internal orchestrator is deprecated and will be removed in a future release.
The native Kubernetes Orchestrator is its replacement. New deployments should standardize on it.
Existing Airflow-based deployments keep working in 2.1 but should plan a migration.
</Note>

<Note>
Classic mode of the interface is deprecated and will be removed in a future release.
AI mode is the replacement. Classic keeps working in 2.1, and the release notes will name the release that
removes it. When it is removed, an organization default or a persona that is still set to Classic moves to AI
mode. Users who switch keep their settings. For more information, see
[Platform, Configuration & Security](/v2.2.x-SNAPSHOT/deployment/upgrade/breaking-changes/platform-and-security#classic-mode-is-deprecated).
</Note>

Several authentication and authorizer settings are deprecated in favor of the email-first settings. The `/{alertType}/resources` alert endpoint is deprecated in favor of `POST /capabilities`.
For more information, see
[Platform, Configuration & Security](/v2.2.x-SNAPSHOT/deployment/upgrade/breaking-changes/platform-and-security) and
[Collaboration: Conversations, Tasks, Announcements, Activity, and Alerts](/v2.2.x-SNAPSHOT/deployment/upgrade/breaking-changes/collaboration).

## Upgrade Checklist

<Steps>
  <Step title="Inventory Your API Clients">
    Search your scripts, dashboards, Terraform files, and continuous integration (CI) jobs for these terms:

    - `/v1/feed`
    - `/v1/glossaryTerms/relationTypes/usage`
    - `sampleDataStorageConfig`
    - The task and suggestion alert event types
  </Step>
  <Step title="Resolve Open Feed Tasks">
    Task threads created through the feed API on 2.0.x are not migrated. Resolve or close the ones you still
    need before you upgrade.
  </Step>
  <Step title="Check for Delta Lake Services">
    Delta Lake services are changed to the Custom Database type and their ingestion pipelines are deleted. Record the
    connection settings you want to keep.
  </Step>
  <Step title="Review Alerts Created by Applications">
    Alerts that came from an application definition are disabled by the migration. Recreate any you still need as
    normal alerts.
  </Step>
  <Step title="Plan Your Sign-In Settings">
    The email-first settings are opt-in. Before you set `emailClaim`, run `openmetadata-ops.sh list-synthesized-emails`
    and fix any entries with `change-email`.
  </Step>
  <Step title="Plan the PostgreSQL Maintenance Window">
    The PostgreSQL migration rebuilds the `isBot` column on `user_entity` under an exclusive lock. Run it in a
    maintenance window if that table is very large.
  </Step>
  <Step title="Run Search Indexing">
    After the upgrade, run the Search Indexing application so the new indexes and mappings are built.
  </Step>
  <Step title="Verify After Upgrade">
    Check the following:

    - Search access for non-admin users
    - Lineage views for restricted users
    - OpenLineage ingestion responses
    - Any OIDC sign-in that relied on OpenMetadata-issued tokens
  </Step>
</Steps>

## Version Scope

The following table shows which versions this section compares.

| | |
| --- | --- |
| **From** | OpenMetadata 2.0.9 (the latest 2.0 release) |
| **To** | OpenMetadata 2.1 |
| **Schema spec** | 217 new schema files, 909 modified files (mostly a one-line dialect change), and six removed files |
| **REST surface** | The `/v1/feed` namespace (13 endpoints) is removed. Many new endpoint groups are added |

<Note>
A few entries reference capabilities that ship only in Collate. They are documented
here because their schemas and REST namespaces are part of the 2.1 specification either way.
</Note>
