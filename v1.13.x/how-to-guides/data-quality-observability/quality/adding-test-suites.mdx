# Adding Test Suites Through the UI
Test Suites are logical container allowing you to group related Test Cases together from different tables. This is a great way to group related test cases together and set a single alert for test case failure.
**Note:** you will need to make sure you have the right permission in OpenMetadata to create a test.

## Step 1: Creating a Test Suite
From the vertical navigation bar, click on `Quality icon > Data Quality` and navigate to the `By Test Suites` tab. From there click on `Add Test Suite` button on the top right corner.

<img src="/public/images/features/ingestion/workflows/data-quality/profiler-tab-view.png" alt="Write your first test" />


On the next page, enter the name and description (optional) of your test suite.

<img src="/public/images/features/ingestion/workflows/data-quality/test-suite-page.png" alt="Create test suite" />


## Step 2: Add Test Cases
On the next page, you will be able to add existing test cases from different entity to your test suite. This allows you to group together test cases from different entities

**Note:** Test Case name needs to be unique across the whole platform. A warning message will show if your Test Case name is not unique.

<img src="/public/images/features/ingestion/workflows/data-quality/test-case-page.png" alt="Create test case" />


## Table Test Suites and Bundle Suites

OpenMetadata has two kinds of test suites. They differ in how they get their owners, which matters when you set up permissions.

| | **Table test suite** | **Bundle Suite** |
|---|---|---|
| **Created** | Automatically, one for each table | By you, as described above |
| **Contains** | The test cases of one table | Test cases from any tables |
| **Owners** | Taken from the table. To change them, change the owners of the table. | Set on the suite itself. |

Because of this, the owner of a table can manage that table's test suite and test cases without extra setup, while the owner of a Bundle Suite doesn't get any rights on the tables of the test cases it contains.

### Let Owners View and Manage Their Tables' Tests

By default, `OrganizationPolicy-Owner-Rule` gives owners full access to the assets they own. For a test case, OpenMetadata checks the owners of the table that the test case belongs to. If you removed or narrowed that rule, use this recipe to let owners view and manage the tests of their own tables:

1. Go to **Settings** > **Policies** and click **Add Policy**. Name it `TableOwnerDataQuality`.
2. Add a rule with these settings:

   | Setting | Value |
   |---|---|
   | **Effect** | Allow |
   | **Resources** | `TestCase`, `TestSuite` |
   | **Operations** | `ViewAll`, `EditAll`, `Create` |
   | **Condition** | `isOwner()` |

3. Add the policy to a role, and assign the role to your data owners or their team.
4. Sign in as an owner, open one of their tables, and confirm that they can view, add, and edit its test cases.

<Note>
The Permission Debugger doesn't list the test case and test suite resources. To check these permissions, sign in as the user and try the action. For more information, see [Permission Debugger](/v1.13.x/how-to-guides/admin-guide/permission-debugger).
</Note>
