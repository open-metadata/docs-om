# Sample Data Handling Using PII Tags

In OpenMetadata, sensitive information is protected through **automatic masking** of sample data when PII (Personally Identifiable Information) tags are applied.

## How It Works

- If a **PII tag** is applied to a **specific column**:
  - Only that column’s sample data will be **masked** and displayed as `******` in the UI.

<img src="/public/images/how-to-guides/governance/pii-tags.png" alt="PII Tag Application at Column Level" />

- If a **PII tag** is applied at the **table level**:
  - **All columns** within that table will have their sample data masked automatically.

<img src="/public/images/how-to-guides/governance/pii-tags2.png" alt="PII Tag Application at Table Level" />

This behavior ensures that sensitive data is not exposed through sample data views in OpenMetadata.

## Example

| Column Name | Tag             | Sample Data Displayed |
|-------------|------------------|------------------------|
| email       | PII.Sensitive    | ******                 |
| phoneNumber | PII.Sensitive    | ******                 |
| age         | (None)           | 25                     |

When the tag is applied at the **table level**, the result would be:

| Column Name | Tag                   | Sample Data Displayed |
|-------------|------------------------|------------------------|
| email       | Inherited from Table   | ******                 |
| phoneNumber | Inherited from Table   | ******                 |
| age         | Inherited from Table   | ******                 |

## How to Apply PII Tags

1. Navigate to the **column** or **table** in the OpenMetadata UI.
2. Apply the **PII.Sensitive** tag via the tagging options.

<img src="/public/images/how-to-guides/governance/pii-tags1.png" alt="PII.Sensitive Tagging" />

3. Ensure auto-classification or manual tagging captures the correct columns during ingestion.

## Access Control

Two separate controls protect sample data:

- **Permission to view sample data.** Sample data has its own `ViewSampleData` operation, and `ViewAll` includes it. A user without it still sees the **Sample Data** tab, but the tab shows a permission-denied message. You can't hide the tab for a role.
- **PII masking.** A column tagged `PII.Sensitive` is masked unless the user is an admin, a bot, or an owner of the table. Having `ViewSampleData` alone doesn't unmask the values.

| User | Has `ViewSampleData` | Sees `PII.Sensitive` values |
|---|---|---|
| Admin, bot, or table owner | Yes | Unmasked |
| Any other user | Yes | Masked (`******`) |
| Any other user | No | Nothing. The tab shows a permission-denied message. |

For sensitive environments:

1. Tag sensitive columns, or the whole table, with `PII.Sensitive`.
2. Assign `ViewSampleData` through a separate role that people join only with approval, instead of through a broad role such as Data Consumer.
3. Make owners of sensitive tables only the people who need to see the real values.
4. To block sample data for a role completely, add a `Deny` rule for `ViewSampleData`. For an example, see [Use Case 11](/v1.13.x/how-to-guides/admin-guide/roles-policies/use-cases#use-case-11-set-up-a-data-owner-role-that-hides-observability).

For more information about permissions, see [Resource Scope and Operations Reference](/v1.13.x/how-to-guides/admin-guide/roles-policies/resource-scope).
