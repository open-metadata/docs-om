# Prerequisites

OpenMetadata provides one setup command for macOS and Linux. Run it from the repository root to
install the toolchain, create the Python virtual environment, generate models, install UI
dependencies, and configure pre-commit hooks.

## Fork and Clone OpenMetadata

<Steps>
  <Step title="Fork the Repository">
    Open the [OpenMetadata repository](https://github.com/open-metadata/OpenMetadata), select
    **Fork**, and create the fork in your GitHub account.
  </Step>
  <Step title="Clone Your Fork">
    Replace `<your-github-username>` with your GitHub username:

    ```shell
    git clone https://github.com/<your-github-username>/OpenMetadata.git
    cd OpenMetadata
    ```
  </Step>
  <Step title="Add the Upstream Remote">
    Keep `origin` pointed at your fork and add the canonical repository as `upstream`:

    ```shell
    git remote add upstream https://github.com/open-metadata/OpenMetadata.git
    git remote -v
    ```
  </Step>
</Steps>

## Set Up the Development Environment

<Steps>
  <Step title="Check the Existing Environment">
    The check reports missing or incompatible tools without changing the system. It returns a
    nonzero exit status when it finds an issue.

    ```shell
    ./scripts/dev_setup.sh --check
    # Or
    make dev_check
    ```
  </Step>
  <Step title="Run the Setup">
    For backend or UI development, use the faster setup:

    ```shell
    ./scripts/dev_setup.sh --slim -y
    ```

    For connector or ingestion development, install all connector dependencies:

    ```shell
    ./scripts/dev_setup.sh -y
    ```

    Pass options through Make with `make dev_setup ARGS="--slim -y"`.
  </Step>
  <Step title="Activate the Environment">
    The setup generates `.dev-env.local.sh` with the selected Java, Node.js, ANTLR, and Python
    paths. Source it in each new shell:

    ```shell
    source .dev-env.local.sh
    ```
  </Step>
</Steps>

## Installed Toolchain

The setup installs or verifies:

- [Docker 20 or later](https://docs.docker.com/engine/install/)
- [Java JDK 21](https://docs.oracle.com/en/java/javase/21/install/overview-jdk-installation.html)
- [ANTLR 4.9.2](https://www.antlr.org/)
- [jq](https://jqlang.github.io/jq/)
- [Maven 3.6 or later](https://maven.apache.org/install.html)
- [Python 3.10 or later](https://www.python.org/downloads/)
- [Node.js 22](https://nodejs.org/en/download/)
- [Yarn Classic 1.22](https://classic.yarnpkg.com/lang/en/docs/install/)

RPM is optional and required only for the Maven RPM profile.

### Python Compatibility

The Python package metadata supports Python 3.10 or later. The setup currently creates development
virtual environments with Python 3.10–3.12 because the pinned spaCy, Thinc, and Blis versions do
not provide wheels for Python 3.13 or 3.14.

### Node.js Compatibility

Use Node.js 22 for UI development. The current `i18next-parser` dependency rejects newer Node.js
major versions. The setup activates Node.js 22 through an existing mise installation or falls back
to a user-local nvm installation.

## Verify the Installation

Run these commands from the repository root after sourcing `.dev-env.local.sh`:

```shell
make prerequisites
python -c "import metadata.generated.schema.entity.data.table"
mvn -q -pl openmetadata-spec install -DskipTests
cd openmetadata-ui/src/main/resources/ui
yarn tsc --noEmit --version
```

## Optional Setup Modes

Use `make dev_setup ARGS="<options>"` or pass options directly to `scripts/dev_setup.sh`:

| Option | Description |
| --- | --- |
| `--check` | Diagnose the environment without changing it. |
| `--slim` | Install core development dependencies without every connector dependency. |
| `--with-build` | Run `mvn clean install -DskipTests -T 1C` after setup. |
| `--with-docker` | Start the local Docker development stack after setup. |
| `--skip-tools` | Verify system packages without installing them. |
| `--skip-python` | Skip the Python virtual environment and ingestion installation. |
| `--skip-ui` | Skip UI dependency installation. |
| `--skip-generate` | Skip model and parser generation. |
| `--skip-precommit` | Skip pre-commit hook installation. |
| `--python <bin>` | Build the virtual environment with a specific compatible interpreter. |

## OpenMetadata API Backend

OpenMetadata uses these technologies for the backend:

- [jsonschema2pojo](https://www.jsonschema2pojo.org/) for Java code generation
- [Dropwizard](https://www.dropwizard.io/en/latest/) for the web service application
- [JDBI3](http://jdbi.org/) for database access
