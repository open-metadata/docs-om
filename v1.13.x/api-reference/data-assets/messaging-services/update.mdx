# Update a Messaging Service

Create a messaging service or update it if it already exists, using `PUT /v1/services/messagingServices` with the full request body. Send the complete definition, not just the fields you want to change. To change only some fields, use `PATCH` with a JSON Patch array and the `application/json-patch+json` content type, as shown in the PATCH examples below.

## Body Parameters

<ParamField body="name" type="string" required>
  Name of the messaging service. Must be unique across all messaging services.
</ParamField>

<ParamField body="serviceType" type="string" required>
  Type of messaging service, for example `Kafka`, `Redpanda`, `Kinesis`, `CustomMessaging`.
</ParamField>

<ParamField body="description" type="string">
  Description of the messaging service in Markdown format.
</ParamField>

<ParamField body="displayName" type="string">
  Human-readable display name for the messaging service.
</ParamField>

<ParamField body="connection" type="object" required>
  Connection configuration specific to the service type.

  <Expandable title="properties">
    <ParamField body="config" type="object">
      Service-specific connection configuration, for example `bootstrapServers`, `securityProtocol` for Kafka.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="owners" type="array">
  Array of owner references (users or teams) to assign to the service.

  <Expandable title="properties">
    <ParamField body="id" type="string">
      UUID of the owner entity.
    </ParamField>

    <ParamField body="type" type="string">
      Type of owner entity, for example `user`, `team`.
    </ParamField>

    <ParamField body="name" type="string">
      Name of the owner entity.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="domains" type="array">
  Fully qualified names of the domains to assign for governance purposes.
</ParamField>

<ParamField body="tags" type="array">
  Array of classification tags to apply to the messaging service.

  <Expandable title="properties">
    <ParamField body="tagFQN" type="string" required>
      Fully qualified name of the tag.
    </ParamField>

    <ParamField body="labelType" type="string">
      Type of label, for example `Manual`, `Derived`, `Propagated`.
    </ParamField>

    <ParamField body="state" type="string">
      State of the tag, for example `Suggested`, `Confirmed`.
    </ParamField>
  </Expandable>
</ParamField>

```python PATCH /v1/services/messagingServices/{id}
import requests

base_url = "https://your-company.open-metadata.org/api"
headers = {
    "Authorization": "Bearer your-jwt-token",
    "Content-Type": "application/json-patch+json"
}

# Update by ID
response = requests.patch(
    f"{base_url}/v1/services/messagingServices/469ef25e-9bdf-4d5f-8553-eb0ce8581f30",
    json=[
        {"op": "replace", "path": "/description", "value": "Updated Kafka messaging service"},
        {"op": "replace", "path": "/displayName", "value": "Sample Kafka (Updated)"}
    ],
    headers=headers
)
updated = response.json()
print(f"Updated to version {updated['version']}")
```

```java PATCH /v1/services/messagingServices/{id}
import org.openmetadata.schema.entity.services.MessagingService;
import org.openmetadata.sdk.fluent.MessagingServices;

// Retrieve, modify, and update
MessagingService service = MessagingServices.retrieve("469ef25e-9bdf-4d5f-8553-eb0ce8581f30");
service.setDescription("Updated Kafka messaging service");
MessagingService updated = MessagingServices.update(service);
```

```bash PATCH /v1/services/messagingServices/{id}

  ]'
```

## Returns

Returns the updated messaging service object with the new version number.

## Response

<ResponseField name="id" type="string">
  Unique identifier for the messaging service (UUID format).
</ResponseField>

<ResponseField name="name" type="string">
  Messaging service name.
</ResponseField>

<ResponseField name="fullyQualifiedName" type="string">
  Fully qualified name of the service.
</ResponseField>

<ResponseField name="description" type="string">
  Updated description.
</ResponseField>

<ResponseField name="version" type="number">
  Incremented version number.
</ResponseField>

## Error Handling

| Code | Error Type | Description |
|------|-----------|-------------|
| `400` | `BAD_REQUEST` | Invalid or malformed request body |
| `401` | `UNAUTHORIZED` | Invalid or missing authentication token |
| `403` | `FORBIDDEN` | User lacks permission to update this messaging service |
| `409` | `CONFLICT` | Concurrent modification detected |
