# Update a Pipeline Service

Create a pipeline service or update it if it already exists, using `PUT /v1/services/pipelineServices` with the full request body. Send the complete definition, not just the fields you want to change. To change only some fields, use `PATCH` with a JSON Patch array and the `application/json-patch+json` content type, as shown in the PATCH examples below.

## Body Parameters

<ParamField body="name" type="string" required>
  Name of the pipeline service. Must be unique across all pipeline services.
</ParamField>

<ParamField body="serviceType" type="string" required>
  Type of pipeline service, for example `Airflow`, `GluePipeline`, `Airbyte`, `Dagster`, `Fivetran`, `DBTCloud`, `Nifi`, `DomoPipeline`, `CustomPipeline`, `Flink`, `KafkaConnect`, `SplineProducer`, `OpenLineage`.
</ParamField>

<ParamField body="connection" type="object" required>
  Connection configuration specific to the service type.

  <Expandable title="properties">
    <ParamField body="config" type="object">
      Service-specific connection configuration, such as the `hostPort` and `connection` fields for Airflow.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="displayName" type="string">
  Human-readable display name for the pipeline service.
</ParamField>

<ParamField body="description" type="string">
  Description of the pipeline service in Markdown format.
</ParamField>

<ParamField body="owners" type="array">
  Array of owner references (users or teams) to assign to the service.

  <Expandable title="properties">
    <ParamField body="id" type="string">
      UUID of the owner entity.
    </ParamField>

    <ParamField body="type" type="string">
      Type of owner entity, for example `user`, `team`.
    </ParamField>

    <ParamField body="name" type="string">
      Name of the owner entity.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="domains" type="array">
  Fully qualified names of the domains to assign for governance purposes.
</ParamField>

<ParamField body="tags" type="array">
  Array of classification tags to apply to the pipeline service.

  <Expandable title="properties">
    <ParamField body="tagFQN" type="string" required>
      Fully qualified name of the tag.
    </ParamField>

    <ParamField body="labelType" type="string">
      Type of label, for example `Manual`, `Derived`, `Propagated`.
    </ParamField>

    <ParamField body="state" type="string">
      State of the tag, for example `Suggested`, `Confirmed`.
    </ParamField>
  </Expandable>
</ParamField>

<RequestExample dropdown>
```bash PUT /v1/services/pipelineServices
curl -X PUT "{base_url}/api/v1/services/pipelineServices" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "sample_airflow",
    "serviceType": "Airflow",
    "description": "Production Airflow pipeline orchestrator",
    "connection": {
      "config": {
        "type": "Airflow",
        "hostPort": "http://localhost:8080",
        "connection": {
          "type": "Backend"
        }
      }
    }
  }'
```

```python PATCH /v1/services/pipelineServices/{id}
import requests

base_url = "https://your-company.open-metadata.org/api"
headers = {
    "Authorization": "Bearer your-jwt-token",
    "Content-Type": "application/json-patch+json"
}

# Update by ID
response = requests.patch(
    f"{base_url}/v1/services/pipelineServices/daa58a49-df05-48a3-a417-45dfd12eacf5",
    json=[
        {"op": "replace", "path": "/description", "value": "Updated Airflow production service"}
    ],
    headers=headers
)
updated = response.json()
print(f"Updated to version {updated['version']}")
```

```java PATCH /v1/services/pipelineServices/{id}
import org.openmetadata.schema.entity.services.PipelineService;
import org.openmetadata.sdk.fluent.PipelineServices;

// Retrieve, modify, and update
PipelineService service = PipelineServices.retrieve("daa58a49-df05-48a3-a417-45dfd12eacf5");

PipelineService updated = PipelineServices.update(service);
```

## Returns

Returns the updated pipeline service object with the new version number.

## Response

<ResponseField name="id" type="string">
  Unique identifier for the pipeline service (UUID format).
</ResponseField>

<ResponseField name="name" type="string">
  Pipeline service name.
</ResponseField>

<ResponseField name="fullyQualifiedName" type="string">
  Fully qualified name of the service.
</ResponseField>

<ResponseField name="description" type="string">
  Updated description.
</ResponseField>

<ResponseField name="version" type="number">
  Incremented version number.
</ResponseField>

## Error Handling

| Code | Error Type | Description |
|------|-----------|-------------|
| `400` | `BAD_REQUEST` | Invalid or malformed request body |
| `401` | `UNAUTHORIZED` | Invalid or missing authentication token |
| `403` | `FORBIDDEN` | User lacks permission to update this pipeline service |
| `409` | `CONFLICT` | Concurrent modification detected |
