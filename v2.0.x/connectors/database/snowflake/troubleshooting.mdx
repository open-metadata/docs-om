## Snowflake User Access Disabled

If you encounter the following error when attempting to connect to a Snowflake database:

```yaml

(snowflake.connector.errors.DatabaseError) 250001 (08001): None: Failed to connect to DB: <your-account>.snowflakecomputing.com:443. User access disabled. Contact your local system administrator.

```

This indicates that the Snowflake user account used for the connection has been **disabled**.


### Resolution

1. **Log in to Snowflake** using an account with administrative privileges.
2. Run the following SQL command to re-enable the user:

   ```sql
   ALTER USER <username> SET DISABLED = FALSE;
    ```

## No View Lineage Is Processed

The lineage workflow log shows `Processing View Lineage` and then `Lineage processing completed with 0/0 chunks processed`, and no lineage is created for views, materialized views or dynamic tables.

`0/0` means the workflow found no view definitions to process. Check the following:

- Run the metadata workflow first. The lineage workflow reads view and dynamic table definitions from the OpenMetadata search index, so the metadata workflow must have stored them and the search index must include them. If it doesn't, run a search reindex. For more information, see [Reindexing Search](/v2.0.x/how-to-guides/admin-guide/reindexing-search).
- Confirm that the views or dynamic tables exist in OpenMetadata under the same service name as the lineage workflow.
- Check the lineage workflow **Database Filter Pattern**, **Schema Filter Pattern** and **Table Filter Pattern**. Filtered-out views are skipped.
- Confirm that **Process View Lineage** is on. If **Incremental Lineage Processing** is on, the workflow skips views that it already processed in an earlier run, so a run with nothing new gives `0/0`.
- Confirm that the Snowflake role used by the metadata workflow can read the definition. If the workflow can't fetch a definition, it ingests the table without one, and the lineage workflow skips it.
