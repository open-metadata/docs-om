# Detect Data Quality Issues with Static Assertions

OpenMetadata uses static data quality assertions to check data against rules you define. These assertions help detect missing values, duplicates, and values outside an expected range.

Dynamic assertions that learn thresholds automatically aren't available in OpenMetadata. Define explicit thresholds for your tests and review them when your data requirements change.

## Choose Validation Rules

Use static assertions for data with known requirements, such as:

- Required values must not be null.
- Identifiers must be unique.
- Numeric values must stay within a defined range.

For example, configure a range test to check that a value stays between 10 and 100. The test reports a failure when the data violates the configured rule.

## Configure and Run Tests

To create and run tests, follow the [data quality configuration guide](/v2.0.x/how-to-guides/data-quality-observability/quality/configure). Select rules and thresholds that match your data requirements, then schedule the data quality workflow.

## Investigate Failures

Use [Incident Manager](/v2.0.x/how-to-guides/data-quality-observability/incident-manager) to investigate failed tests, assign incidents, and track resolution.

For notifications about test failures, configure [data observability alerts](/v2.0.x/how-to-guides/data-quality-observability/alerts-notifications/data-observability-alerts).
