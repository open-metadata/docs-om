# How to Create a Custom Property for a Data Asset

OpenMetadata uses a schema-first approach, and that's why we support custom properties for all types of data assets. Organizations can extend the attributes as required to capture custom metadata. You can view the Custom Properties tab in the detailed view for all types of data assets.

## Who Can Create Properties and Set Values

- **Create or change a property definition**: Only administrators can add, edit, or delete a property in **Settings** > **Custom Properties**. A property adds a field to an asset type across the whole instance, so the permission is restricted. If you don't see **Add Custom Property**, ask an administrator to create the property.
- **View properties and set values**: Other users, such as data stewards, can see the properties on an asset. They can set values on individual assets if their role grants the permission to edit custom properties on that asset.

Supported types:

- Date
- Date Time
- Duration
- Email
- Entity Reference
- Entity Reference List
- Enum
- Integer
- Markdown
- Number
- SQL Query
- String
- Table
- Time
- Time Interval
- Timestamp

To create a Custom Property in OpenMetadata:
- Navigate to **Settings** >> **Custom Properties**
- Click on the type of data asset you would like to create a custom property for.
- Click on **Add Property**

<img src="/public/images/how-to-guides/discovery/custom1.png" alt="Create a Custom Property" />

- Enter the required details: `Name`, `Type`, and `Description`. You can lookup for the details of the information asked on the right side panel.
  - **Name:** The name must start with a lowercase letter, as preferred in the camelCase format. Uppercase letters and numbers can be included in the field name; but spaces, underscores, and dots are not supported.
  - **Type:** Type of custom property like `entityReference`, `email`, etc.
  - **Description:** Describe your custom property to provide more information to your team.
- Click on **Create**.

<img src="/public/images/how-to-guides/discovery/custom2.png" alt="Define a Custom Property" />

<Warning>
You can't change a custom property's **Name** after you create it. You can still edit its **Display Name** and **Description**. To change the name itself, delete the property and create it again with the new name. The values you entered for the old property aren't carried over to the new one, and deleting the property removes its values from every asset of that type. Copy the values you need before you delete the property.
</Warning>

Once the custom property has been created for a type of data asset, you can add the values for the custom property from the Custom Property tab in the detailed view of the data assets.

<img src="/public/images/how-to-guides/discovery/custom3.png" alt="Enter the Value for a Custom Property" />

## Set Values in Bulk

A property is defined once for an asset type and appears on every asset of that type. There's no step to assign it to assets. To fill in values on many assets at once, use one of these methods. Create properties one at a time in **Settings** > **Custom Properties**. Uploading a file to define properties isn't supported.

### Import Values from a CSV File

Export the assets, add values to the CSV file, and import it again.

1. Open the database schema, then export its tables as a CSV file. For more information, see [Import Data Assets](/v2.0.x/how-to-guides/data-discovery/import).
2. In the `extension` column of each row, enter the values to set.
3. Import the file and review the preview. Fix any row marked **Failed** before you continue.

Write each value as `propertyName:value`. Use the property **Name**, not the **Display Name**. Separate several properties in one cell with a semicolon (`;`). Separate several values of one property with a pipe (`|`). When a cell holds more than one property, enclose the whole cell value in double quotes.

```csv
"businessOwner:user:jane.doe;slaTier:Gold;aliases:net|sales"
```

In this example:

- `businessOwner:user:jane.doe`: An **Entity Reference** property. The value is the entity type and the fully qualified name, here a user.
- `slaTier:Gold`: A property with a single value.
- `aliases:net|sales`: A property with two values.

<Note>
**Note**: CSV import can't set **Hyperlink** properties, and **Number** properties accept whole numbers only. A decimal value fails the row. Set these values from the asset page.
</Note>

### Edit Values in a Grid

On the **Tables** tab of a database schema, click **Edit** to open the grid editor. It lists the tables and their `extension` values, and you can change several rows before you save. The **Edit** button appears only if you have edit permission on the schema.

To delete a Custom Property for a particular asset, such as tables, navigate to **Settings >> Custom Properties >> Tables** and
 click on **Delete Property**
