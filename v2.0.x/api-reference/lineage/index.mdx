# Lineage

The Lineage APIs let you query and manage relationships between OpenMetadata assets. Native endpoints accept entity IDs or fully qualified names. OpenLineage endpoints accept events with input and output datasets.

Use the native API when your application already identifies the catalog assets to connect. Use the OpenLineage API when your pipeline emits `RunEvent` payloads. For more information, see [OpenLineage Compatibility](/v2.0.x/how-to-guides/data-lineage/openlineage).

## Authentication and Permissions

Send your OpenMetadata JWT in the `Authorization: Bearer` header. Native lineage writes require `EditLineage` permission on both endpoint entities. OpenLineage event submission requires `EditLineage` permission on the `table` resource.

Endpoint paths in these pages are relative to the API base URL. For example, `/v1/lineage` is served at `https://your-company.open-metadata.org/api/v1/lineage`.

For more information, see [API Authentication](/v2.0.x/api-reference/authentication).

## Supported Entity Types

Lineage connects data assets such as tables, dashboards, pipelines, topics, and ML models. Common combinations include:

| From | To | Example |
|------|-----|---------|
| Table | Table | ETL transformations between source and target tables |
| Table | Dashboard | Dashboards consuming data from tables |
| Pipeline | Table | Pipelines producing data into tables |
| Topic | Table | Streaming data from Kafka topics into tables |
| Table | ML Model | Tables used as training data for ML models |

## Key Concepts

- **Edge**: A directional lineage relationship from one entity to another
- **Column-level lineage**: Mapping specific columns from a source entity to columns in a target entity
- **Pipeline reference**: Associating a pipeline entity that powers the transformation
- **Upstream/Downstream depth**: Controls how many hops to traverse when querying the lineage graph
