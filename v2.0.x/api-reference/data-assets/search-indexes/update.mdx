# Update a Search Index

Create a search index or update it if it already exists, using `PUT /v1/searchIndexes` with the full request body. Send the complete definition, not just the fields you want to change. To change only some fields, use `PATCH` with a JSON Patch array and the `application/json-patch+json` content type, as shown in the PATCH examples below.

## Body Parameters

<ParamField body="name" type="string" required>
  Name of the search index. Must be unique within the parent search service.
</ParamField>

<ParamField body="service" type="string" required>
  Fully qualified name of the parent SearchService, for example `elasticsearch_sample`.
</ParamField>

<ParamField body="fields" type="array">
  Array of field objects defining the index schema.

  <Expandable title="properties">
    <ParamField body="name" type="string">
      Name of the field.
    </ParamField>

    <ParamField body="dataType" type="string">
      Data type of the field, for example `TEXT`, `KEYWORD`, `INT`, `OBJECT`.
    </ParamField>

    <ParamField body="description" type="string">
      Description of the field.
    </ParamField>

    <ParamField body="children" type="array">
      Nested child fields for complex types.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="displayName" type="string">
  Human-readable display name for the search index.
</ParamField>

<ParamField body="description" type="string">
  Description of the search index in Markdown format.
</ParamField>

<ParamField body="owners" type="array">
  Array of owner references (users or teams) to assign to the search index.

  <Expandable title="properties">
    <ParamField body="id" type="string">
      UUID of the owner entity.
    </ParamField>

    <ParamField body="type" type="string">
      Type of owner entity, for example `user`, `team`.
    </ParamField>

    <ParamField body="name" type="string">
      Name of the owner entity.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="domains" type="array">
  Fully qualified names of the domains to assign for governance purposes.
</ParamField>

<ParamField body="tags" type="array">
  Array of classification tags to apply to the search index.

  <Expandable title="properties">
    <ParamField body="tagFQN" type="string" required>
      Fully qualified name of the tag.
    </ParamField>

    <ParamField body="labelType" type="string">
      Type of label, for example `Manual`, `Derived`, `Propagated`.
    </ParamField>

    <ParamField body="state" type="string">
      State of the tag, for example `Suggested`, `Confirmed`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="extension" type="object">
  Custom property values defined by your organization's metadata schema.
</ParamField>

<RequestExample dropdown>
```bash PUT /v1/searchIndexes
curl -X PUT "{base_url}/api/v1/searchIndexes" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "table_search_index",
    "displayName": "TableSearchIndex",
    "service": "elasticsearch_sample",
    "description": "Search index for table entities",
    "fields": [
      {"name": "name", "dataType": "TEXT"},
      {"name": "description", "dataType": "TEXT"}
    ]
  }'
```

```python PATCH /v1/searchIndexes/{id}
from metadata.sdk import configure
from metadata.sdk.entities import SearchIndexes

configure(
    host="https://your-company.open-metadata.org/api",
    jwt_token="your-jwt-token"
)

# Retrieve, modify, and update
si = SearchIndexes.retrieve("f5b0fa81-f241-4508-9219-dae31dcced18")
si.description = "Updated: Search index for table entities with enhanced mapping"
updated = SearchIndexes.update(si)

print(f"Updated to version {updated.version.root}")
```

```java PATCH /v1/searchIndexes/{id}
import org.openmetadata.schema.entity.data.SearchIndex;

// client is an initialized OpenMetadataClient.

// Retrieve, modify, and update
SearchIndex searchIndex = client.searchIndexes().get("f5b0fa81-f241-4508-9219-dae31dcced18");
searchIndex.setDescription("Updated: Search index for table entities with enhanced mapping");
SearchIndex updated = client.searchIndexes().update(searchIndex.getId(), searchIndex);
```

```bash PATCH /v1/searchIndexes/{id}
# Update by ID
curl -X PATCH "{base_url}/api/v1/searchIndexes/f5b0fa81-f241-4508-9219-dae31dcced18" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "replace", "path": "/description", "value": "Updated search index for table entities"}
  ]'

# Update by name
curl -X PATCH "{base_url}/api/v1/searchIndexes/name/elasticsearch_sample.table_search_index" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json-patch+json" \
  -d '[
    {"op": "replace", "path": "/description", "value": "Updated search index for table entities"}
  ]'
```

## Returns

Returns the updated search index object with the new version number.

## Response

<ResponseField name="id" type="string">
  Unique identifier for the search index (UUID format).
</ResponseField>

<ResponseField name="name" type="string">
  Search index name.
</ResponseField>

<ResponseField name="fullyQualifiedName" type="string">
  Fully qualified name in format `service.indexName`.
</ResponseField>

<ResponseField name="description" type="string">
  Updated description.
</ResponseField>

<ResponseField name="version" type="number">
  Incremented version number.
</ResponseField>

## Error Handling

| Code | Error Type | Description |
|------|-----------|-------------|
| `400` | `BAD_REQUEST` | Invalid or malformed request body |
| `401` | `UNAUTHORIZED` | Invalid or missing authentication token |
| `403` | `FORBIDDEN` | User lacks permission to update this search index |
| `409` | `CONFLICT` | Concurrent modification detected |
