## Requirements
Note that we support an Exasol database version 8 or later. Ensure your Exasol instance meets this minimum version requirement before proceeding.

### Metadata
To ingest basic metadata, an Exasol user must have the following privileges:
  - `USAGE` privilege on the schema
  - `SELECT` privilege on the tables

For more information, see the [Exasol Privileges page](https://docs.exasol.com/db/latest/database_concepts/privileges.htm).

Use the following SQL commands to grant these privileges to the OpenMetadata ingestion user:

```sql
GRANT USAGE ON <schema_name> TO <ingestion_username>;
GRANT SELECT ON TABLE <schema_name>.<table_name> TO <ingestion_username>;
```

Alternatively, grant privileges to allow access to all schemas and tables:

```sql
GRANT USE ANY SCHEMA TO <ingestion_username>;
GRANT SELECT ANY TABLE TO <ingestion_username>;
```
<Tip>
Use these broader privileges only when access to all schemas and tables is intended. `SELECT ANY TABLE` does not include system tables; the lineage & query usage workflows still require `SELECT ANY DICTIONARY`.
</Tip>

### Lineage & Query Usage
For the lineage & query usage workflows, OpenMetadata fetches query logs by querying
`EXA_STATISTICS.EXA_DBA_AUDIT_SQL` and joining with `EXA_STATISTICS.EXA_DBA_AUDIT_SESSIONS`.
To access these system tables, an Exasol user must have the `SELECT ANY DICTIONARY` system
privilege, and auditing must be enabled on the database. For more information about Exasol auditing, see
[Auditing](https://docs.exasol.com/db/latest/database_concepts/auditing.htm#Implementation).

Grant the required system privilege to the OpenMetadata ingestion user:

```sql
GRANT SELECT ANY DICTIONARY TO <ingestion_username>;
```

# Connection Options
<Steps>
<Step title="Connection Options">
- **Connection Scheme**: Specifies the SQLAlchemy driver scheme options required to connect to Exasol.
- **Username**: The username used to connect to the Exasol database. Ensure that this user has sufficient privileges to read all the metadata from Exasol.
- **Password**: The password associated with the user connecting to Exasol.
- **Host and Port**: Defines the host and port of the Exasol instance. Provide this as a string in the format `hostname:port`. For example: `localhost:8563`
  - If running the OpenMetadata ingestion in a Docker container and your services are hosted on `localhost`, use `host.docker.internal:8563`.
- **SSL/TLS Settings**: Specifies the mode or settings for SSL/TLS validation during the connection. Available options:
  - **validate-certificate (Default)**: Enables Transport Layer Security (TLS) and validates the server certificate using system certificate stores.
  - **ignore-certificate**: Enables Transport Layer Security (TLS) but disables validation of the server certificate.
    <Tip>
    This mode should **never** be used in production. It is useful for testing with self-signed certificates.
    </Tip>
  - **disable-tls**: Disables Transport Layer Security (TLS). Data is sent in plain text (no encryption).
    <Tip>
    This mode should **never** be used in production and should only be used in debugging scenarios.
    </Tip>
</Step>
